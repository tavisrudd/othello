* DONE B1: Define the evidence boundary and producer record

The ordinary =evaluate= API should remain a compact checked closure. An explicit evidence API will retain a source-bound chain for transfer. It must capture bytes of each prepared layer, both encoded certificates, a digest of each with distinct domain tags, every declared relation's name/arity/input flag, each input's canonical tuple digest, and each non-positive literal's generated relation. The producer verifies both certificates and the construction records before returning either result. Evidence allocation and encoding occur only on the opt-in cold path; no derivation-loop operation changes.

The source identity is the core prepared identity recomputed from bytes. A content digest is a reference, not a substitute for carrying bytes. The offline reader must get enough data to re-admit all layers and check both certificates without the producer's =Demand= plan.

The agreed envelope is an opt-in serializable =EvidenceArtifact= returned beside the ordinary =Stratified=. It carries original source bytes and a tagged source digest, the normalized RIR fingerprint, the body policy and effective frontend limits, validated external seed names with arity/count/digest, and one =LayerEvidence= per layer. A layer carries canonical prepared bytes and their core prepared identity, declared relation metadata, per-input tagged tuple digests, literal-to-materialization mappings, and both certificate byte streams with tagged digests. A wire DTO carries the typed dictionary/readout, construction records and final closure. This DTO avoids making the core evaluator's policy enum part of the wire format; its copies are made only on the opt-in path. The ordinary =Stratified= result remains compact. The layer-zero prepared source supplies the actual claimed external rows, so they need not be copied into the envelope a second time.

The current raw JSON certificate SHA-256 values in benchmark receipts remain unchanged. The evidence digests use tagged records; they are new identities, not replacements for those existing receipts. =BodyPolicy= and =Limits= are written through explicit wire fields, because the frontend source compiles in a standalone parity harness without Cargo dependencies.

Initial code review found a missing use-site entry for a second literal sharing an aggregate result. The first producer diff incremented the aggregate record's =uses= count but skipped the literal-to-result mapping on that reuse branch. The producer is repairing it; a shared-aggregate fixture belongs in the adversarial gate.

The first source-aware check also compared a shared filter record's single representative =literal= against *every* use site's literal, which would reject an honest shared filter. Review requested a representative check plus checks of each mapped use. The aggregate check must bind its recorded aggregated column to the source literal as well as its relation and operator. These are source-binding requirements, not just record-shape checks.

Digest framing is length-delimited. The shared outer frame is =SHA256("ergodis.rel-stratified.evidence.v1/" || field || 0x00 || u64le(payload_length) || payload)=. An input payload carries its relation name, arity, row count, tuple-byte length and canonical little-endian tuple values. A construction record uses field =record= and additionally prefixes the payload with its kind; the relation name and arity precede count and tuple bytes. Thus an equal tuple vector in different relation kinds, names or arities has a different record digest. The verifier restates this framing independently.

The producer implementation is integrated. Its targeted tests pass 4/4, the stratified unit group 10/10, and the pinned Nix Rel lowering integration suite 76/76. Source-aware per-layer mapping checks run inside evaluation; a positive layer with no nonpositive literal skips the new mapping audit, and a nonpositive result replays its construction records before return. The typed result's ordinary output fields remain unchanged.

** Red-team checks

- A chain may omit or duplicate a construction, relation, literal, or layer. The reader must compare inventories derived from the recorded layer source and the original Rel source, rather than only replay supplied records.
- A record may describe correct tuples for the wrong literal, operator, relation, layer, or dictionary state. The reader must bind each to an independently parsed use site and to the checked prior closure.
- A dictionary-dependent filter or aggregate can change meaning when a later aggregate interns values. The record must fix its dictionary boundary; replay must refuse a value not present at that boundary.
- An input digest alone is weak if the source bytes are absent. The reader must recompute it over the re-admitted input rows and establish provenance from earlier checked relations or validated external seeds.
- Matching two certificates is insufficient if they share an invalid source. Both checker doors must independently re-admit the encoded source, and the recorded identity must equal the bytes' identity.
- Deserialization must bound sizes before allocation and report a record kind, index, and field on failure. The decode path must not treat untrusted lengths as preallocation advice.
- The envelope's frontend limits are untrusted values. A small file can request enormous workspace reservations. The offline verifier must cap both individual capacities and their estimated total before constructing a workspace, with explicit higher budgets for large legitimate evidence.

* DONE B2: Implement independent offline verifier and tool command

Use a separately written, set-based construction rebuild promoted from the test reference approach, as accepted in the card. It must not call =Demand= or the producer's complement/filter/aggregate construction functions. Re-admit each layer's bytes and check both certificates with =ergodis-verify=, then compare their checked closures relation by relation. Rebuild and compare constructions and inputs from prior checked closures. Provide a library API and an =ergodis-tools= subcommand that reads an evidence file in a new process.

Root review found a source-provenance gap in the first verifier draft: it checked source facts as a subset of the prepared base facts for a derived relation. That would admit arbitrary extra base facts if an attacker re-certified the forged layer. The verifier must require exact equality to the re-lowered source fact set for every derived relation; only explicitly named free input relations can include validated external rows. A separate guard must check the computed complement/filter product before enumerating it, so malformed metadata cannot force an unbounded offline replay.

Both repairs landed. The independent verifier re-lowers original source bytes, reconstructs each layer's declared relation and full rule shape, admits canonical prepared bytes, checks trace and ranked certificates separately, and carries only their checked closures across layers. It rebuilds aggregate groups and dictionary interning, complement sets and comparison pairs using separate set-based algorithms; it checks the exact prepared facts, record fields/digests, final typed dictionary and relation closures. It computes domain and materialization bounds from the re-lowered RIR and admitted layers before replay allocation. The transfer report contains only source-derived counts and certified derivation counts. Evaluator rounds, probes, candidates and index policy remain diagnostic fields of the ordinary result.

Independent Sol review of private =6a97b55= found that appended construction records with a layer number outside the chain escaped per-layer checks. A global layer-range check now rejects each record family, and a mutation test covers all three. The review also observed that evaluator-only counters could be altered without an independent check. The transferable =EvidenceLayerReport= now omits those counters entirely. Recorded workspace limits are replay capacities chosen by the producer; they are bounded for allocation safety but are not a semantic source claim.

The reviewer raised a possible fact-plus-rule accounting defect, then traced the lowerer's invariant: a fact-set definition becomes =REL_INPUT=, a formula definition becomes =REL_DERIVED=, and a second definition of the same relation is rejected. Thus one admitted RIR relation cannot mix source facts and rules; no code change was retained for that non-finding. The reviewed path has no other identified correctness defect. The independent audit used Sol xhigh, as requested for this implementation lane; the card originally called for Opus, which is unavailable in the current agent set.

The initial converter compared admitted facts by cloning every tuple into two sortable vectors. Code review replaced that with one sorted index vector over the wire admission. ** Pre-measurement cost model

The opt-in artifact allocates roughly one copy of the final closure and records plus encoded prepared/certificate bytes; this is paid only by the writer. Its SHA-256 work is linear in those bytes, outside evaluation. The ordinary derivation loop receives no new per-candidate branch or allocation. Source/seed validation is linear in supplied external values; the default empty seed list has only a branch. A source-aware construction replay is proportional to each materialized construction universe and aggregate input set. The producer now records a =has_materialization= flag during its existing layer-rule scan: a positive layer with no recorded use skips the new per-layer mapping audit, while a layer containing a nonpositive literal still audits the complete use inventory even if a producer bug omitted its record. A positive final result also skips the full record replay. The binary grows from the new CLI command and may shift untouched ThinLTO code; retained A/B, not source inspection, decides that risk. The exporter performs two cold admissions plus a fact-set comparison and is not on the default route.
