planes of order 12. **No result here bears on the prime-power conjecture, on the
existence of a plane of order 12, or on the dossier's promotion gate.** The promotion

## Case 1: no point-regular collineation group at order 12

**Statement.** A projective plane of order 12 has no collineation group acting
regularly on points. Equivalently, no planar `(157, 13, 1)` difference set exists.

**Reduction.** A plane of order 12 has `v = 157` points and `157` lines, `13` points
per line. `157` is prime, so every group of order 157 is cyclic; a cyclic group acting
regularly on the points of a plane of order `n` is equivalent to a planar
`(n^2+n+1, n+1, 1)` difference set in `Z_v`. So the restricted case is exactly the
nonexistence of a planar difference set with `v = 157`, `k = 13`, `n = 12`.

**Certificate A: numerical-multiplier orbits (instant).** Every prime `p` dividing
`n = 12` with `p` coprime to `v` is a numerical multiplier of a planar difference set,
and the set may be translated so that every numerical multiplier fixes it setwise. Here
`n = 12 = 2^2 * 3` and `gcd(6, 157) = 1`, so `2` and `3` are multipliers. Exact
computation gives multiplicative orders `ord_157(2) = 52` and `ord_157(3) = 78`, and the
subgroup they generate is the whole of `(Z/157)^*`, of order `156`. Its orbits on `Z_157`
are `{0}` (size 1) and `Z_157 \ {0}` (size 156). A multiplier-fixed difference set is a
union of orbits, so its size lies in `{0, 1, 156, 157}`. `13` is not among them.

(`schema c1018.plane12.multiplier.v1`), fields `multiplier_orders = [52, 78]`,
`group_order = 156`, `orbit_sizes = [1, 156]`, `representable = false`.

**Certificate B: exhaustion independent of the multiplier theorem.** Exhaustive

of a plane of order 12 fixes no point, then every point orbit has size `p`, so

**every prime-order collineation of a hypothetical plane of order 12 fixes at least one
point, and dually at least one line.**

## Case 2: a collineation of order 13

`13 = n + 1` is the smallest prime for which the fixed structure is forced to be as small
as possible, which is what makes the case exactly computable.

**Reduction to a tactical decomposition.** Let `s` be a collineation of order 13 of a
plane of order 12 and `f` the number of fixed points.

1. `f` equals the number of fixed lines (the standard trace argument on the incidence
   permutation matrices).
2. Non-fixed points lie in orbits of size 13, so `f = 157 mod 13 = 1 mod 13`.
3. The fixed structure is closed under joins and meets. If it contains a quadrangle it
   is a subplane of order `m`; a subplane of a plane of order `n` satisfies `m^2 = n`
   (Baer) or `m^2 + m <= n`. `12` is not a square, so `m <= 3` and `f` is `7` or `13`,
   neither congruent to `1` modulo `13`. Otherwise the fixed structure is degenerate:
   either all fixed points are collinear, giving `f <= 13`, or it is a near-pencil - a
   line `L` carrying `s'` fixed points, a point `P` off `L`, and the `s'` joins - giving
   `f = s' + 1 <= 14`. The value `f = 14` forces `s' = 13`, so `s` fixes `L` pointwise
   and is a perspectivity, whose order divides `n = 12` (elation) or `n - 1 = 11`
   (homology); `13` divides neither. Hence `f = 1`.
4. With `f = 1`, call `P` the fixed point and `L` the fixed line. If `P` were on `L`,
   then `s` would permute the remaining 12 points of `L` in orbits of size 13, which is
   impossible. So `P` is not on `L`.
5. Therefore the point orbits are `{P}` together with 12 orbits of size 13, one of which
   is the point set of `L`; dually the line orbits are `{L}` together with 12 orbits of
   size 13, one of which is the pencil through `P`.

**The orbit matrix.** For a point orbit `O_i` and a line orbit `M_j`, both of size 13,
the number `a_ij` of points of `O_i` on a line of `M_j` is independent of the chosen
line, and equals the number of lines of `M_j` through a chosen point of `O_i`. Because
every line other than `L` meets `L` in exactly one point, the row indexed by `L` is all
ones; dually, because every point other than `P` lies on exactly one line of the pencil
through `P`, the column indexed by that pencil is all ones. Deleting that row and column
leaves an `11 x 11` nonnegative integer matrix `B` satisfying

```text
row sums     = 12          column sums = 12
sum_j b_ij^2 = 24          sum_j b_ij b_kj = 12   (i != k)
equivalently  B B^T = 12 (I_11 + J_11),  det B = +/- 12^6.
```

The only multisets with 11 nonnegative parts, sum 12 and square sum 24 are
`(2^6)`, `(3, 2^3, 1^3)`, `(3^2, 1^6)` and `(4, 1^8)`, giving 51 777 candidate rows.

**Outcome: reduced, not eliminated - and provably so at this level.** The orbit-matrix
equation is solvable. Explicit witness: let `N` be the incidence matrix of the Paley
biplane, the symmetric `2-(11,5,2)` design whose blocks are the translates of the
quadratic residues modulo 11, and let `N'` be the complementary `2-(11,6,3)` design.
Then `B = 2 N'` has row and column sums `6 * 2 = 12`, row square sums `6 * 4 = 24`, and
pairwise row dot products `4 * 3 = 12` because two blocks of a symmetric `2-(11,6,3)`
design meet in exactly 3 points. This witness is verified in the Python helper
(`order12_biplane_witness_valid = true`).

A second, structurally different witness was produced by the driver itself with
`--cap 1` after 322 094 nodes, showing that the solution set is not confined to the
biplane family. Its row-type profile is one `(4,1^8)` row, one `(3^2,1^6)` row, eight
`(3,2^3,1^3)` rows and one `(2^6)` row:

```text

 0 1 1 1 1 1 1 3 3 0 0
 1 0 0 0 1 2 3 0 2 1 2
 1 0 0 2 2 2 0 1 1 3 0
 1 0 1 3 0 0 2 2 0 1 2
```

**Where the boundary landed.** An order-13 collineation of a plane of order 12 cannot be
excluded by orbit counting or by the tactical decomposition alone; the elimination must
come from lifting an orbit matrix to an actual incidence structure on 157 points, which
is a strictly larger search and is out of scope for this wave.

The remaining orbit-matrix deliverable - the exact count of solutions up to the
normalization - is **infeasible this wave and was deliberately abandoned rather than left
running**: the solution set is already known to be nonempty and structurally
heterogeneous, so its cardinality carries no elimination content, and a capped probe
shows solutions appearing after a few hundred thousand nodes, implying a large count. The
exhaustive run was stopped after roughly ten minutes without completing. The down-scoped
statement that this wave does prove is the reduction itself: *an order-13 collineation of
a plane of order 12 has exactly one fixed point and one fixed line, they are
non-incident, and its tactical decomposition is an `11 x 11` nonnegative integer matrix
`B` with `B B^T = 12(I + J)` and constant row and column sums 12* - together with the
proof that this system is solvable, so no contradiction lives at this level.

**Method control at order 6.** The identical machinery, run at `n = 6`, `p = 7`
(`v = 43`, `f = 1 mod 7`, `dim 5`, row sums 6, row square sums 12, pairwise dots 6),
returns **zero** orbit matrices. So a projective plane of order 6 admits no collineation
of order 7, proved here by exhaustion over the tactical decomposition, and the machinery
does eliminate when elimination is possible at this level. Positive controls `n = 2`
(`p = 3`) and `n = 4` (`p = 5`) each return exactly one orbit matrix, as they must, since
`PG(2,2)` and `PG(2,4)` have such collineations. At `n = 10`, `p = 11` the search returns
3 024 normalized orbit matrices with the single row-type profile `[8, 1]`.

## Case 3: a hyperoval invariant under the order-13 collineation

**Why hyperovals and not ovals.** `12` is even, and in a plane of even order the tangents
to an oval are concurrent at the nucleus, so every oval extends uniquely to a hyperoval.
The oval and hyperoval cases at order 12 are therefore the same case, and it is stated
for hyperovals: `|H| = n + 2 = 14`, every line meets `H` in 0 or 2 points, there are
`C(14,2) = 91` secants and `157 - 91 = 66` external lines, and each of the 143 points off
`H` lies on exactly 7 secants and 6 external lines (`143 * 7 = 1001 = 91 * 11`).

**Forced structure under an order-13 collineation.** Let `s` have order 13 with fixed
point `P` and fixed line `L`, and let `H` be `s`-invariant.

1. `H` is a union of `s`-orbits and `|H| = 14 = 13 + 1`, so `H = {P} u O` for a single
   point orbit `O`. In particular the fixed point lies on the hyperoval.
2. `L` is external to `H`: if a point of `O` lay on `L`, its whole 13-point orbit would
   lie on `L`, so `L` would be contained in `H`, contradicting that `H` is an arc.
3. The pencil column of the orbit matrix is all ones, so each of the 13 lines through `P`
   meets `H` in `P` and exactly one further point - the arc condition on the pencil is
   automatic.
4. `H` is an arc if and only if the row of `O` in `B` has all entries at most 2, which by
   the row classification above means the row is of type `(2^6)`.

**The one-factorization bridge (exact, and of independent interest).** For any hyperoval
`H` in any plane of order 12 and any point `R` off `H`, the 7 secants through `R`
partition `H` into 7 pairs, that is, `R` determines a perfect matching of the complete
graph `K_14` on `H`. If `l` is an external line, every one of the 91 secants meets `l` in
exactly one point, so the 13 matchings determined by the points of `l` partition the edge
set of `K_14`: **every external line of a hyperoval in a plane of order 12 induces a
one-factorization of `K_14` on the hyperoval.**

Under `s`, the external line `L` is fixed and its 13 points form a single orbit, so the
induced one-factorization of `K_14` on `H = {P} u O` - identify `P` with a fixed vertex
and `O` with `Z_13` - is invariant under `x -> x + 1` with its 13 one-factors forming a
single orbit. Such one-factorizations are exactly the **starters in `Z_13`**: a partition
of `Z_13 \ {a}` into 6 pairs whose 6 difference classes `{d, -d}` are all distinct.

**Outcome: reduced, not eliminated.** Exhaustive enumeration over all 10 395 pairings of
`Z_13 \ {0}` finds **133 starters**; the remaining 10 262 pairings are rejected, each with
an explicit Hall-deficient set (two pairs competing for one difference class) as the
witness. The patterned starter `{{i, -i} : i = 1..6}` is among them, so the case survives.

Certificate: `~/.cache/ergodis/c1018/starter-13.json`
(`schema c1018.plane12.starter.v1`), fields `partitions_examined = 10395`,
`starters = 133`, `hall_saturated = 133`, `hall_deficient = 10262`.

The elimination boundary for the invariant-hyperoval case is therefore the joint
compatibility of a starter with an orbit matrix having a `(2^6)` row, plus the lifting to
an actual incidence structure - the same lifting barrier as Case 2.

## Ergodis interface notes

The driver is `ergodis-private/src/bin/c1018_plane12.rs`, a new binary added under the
existing `src/bin` autodiscovery; no existing file in `ergodis-private` and nothing in
the read-only Ergodis core was modified, and no `Cargo.toml` entry was needed.

**What fitted.** `ergodis_private::hall_core::HallWorkspace` is the right primitive for
every "each object must claim its own slot" condition in this problem, and it is used
load-bearingly in two places.

- *Difference sets.* Left vertices are the `C(k,2)` unordered pairs of a candidate set,
  right vertices are the `(v-1)/2` difference classes `{d, v-d}`, and a pair is adjacent
  to the class it realizes. The set is a planar difference set exactly when the matching
  saturates the left side. `HallOutcome::Deficient` returns the alternating-reachable
  left set and its neighbourhood, and that pair *is* the elimination witness: a set of
  pairs whose realized difference classes are too few.
- *Starters.* Left vertices are the `(m-1)/2` pairs of a candidate pairing of
  `Z_m \ {0}`, right vertices are the `(m-1)/2` difference classes. Saturation is exactly
  the starter condition; the 10 262 rejections in the `Z_13` enumeration are each
  returned with a Hall-deficient set.

The workspace allocates once and is reused across the whole search, which is what makes
the per-candidate certification affordable inside a backtracking loop; `solve` validates
the CSR shape and returns `HallError` rather than panicking, so a malformed graph is
caught rather than silently mismatched.

**What did not fit, and what was written instead.** The orbit-matrix condition is a
degree-constrained matrix completion, not a matching: the constraints are row sums,
column sums, row square sums and pairwise row inner products, and its natural relaxations
are Gale-Ryser and flow conditions, not Hall's condition. Forcing `hall_core` onto it
would have produced a decorative rather than a load-bearing certificate, so the
orbit-matrix search uses its own row enumeration, column-capacity pruning and pairwise
inner-product filtering. The Ergodis core modules `orbit`, `orbit_compile`, `incidence`
and `projective` were inspected as candidate hosts; they are built around the repository's
repair-port and rank problems and none of them exposes a general "orbit matrix of a
symmetric design under a prime-order automorphism" abstraction. **No core modification
was required and none was made.** If this line is continued, the reusable piece worth
promoting is exactly that abstraction - a tactical-decomposition solver parameterized by
`(v, k, lambda, p)` - and it belongs in `ergodis-private` first.

## Novelty posture

The classes eliminated here are classical. Nonexistence of a cyclic plane of order 12 is
covered by the Evans-Mann style multiplier and exhaustion arguments for planar difference
sets, and the collineation groups of hypothetical planes of orders 10 and 12 have a
substantial literature. **No literature-audit pass was run in this wave**, so the report
makes no priority or novelty claim, and none of these statements should be presented as
new. What the wave adds is a replayable, independently checked certificate for each, plus
the explicit statement of the order-13 tactical decomposition and the hyperoval
one-factorization bridge in a form the repository can build on. The dossier's promotion
gate - a certified *new* nonexistence class at order 12 - is **not** met.

## Crosswalk discipline

Nothing above bears on the prime-power conjecture for finite projective planes. Each
result is conditional in the same way: it says that *if* a projective plane of order 12
exists, *then* it does not carry a particular symmetry or configuration. A plane of order
12 with no collineation of prime order at all is untouched by every argument here, and
that is the generic case. Nor is any statement here evidence for or against the existence
of a plane of order 12; eliminating symmetric cases is exactly the part of the problem
that is easy, and the literature on order 10 shows the unrestricted case is many orders
of magnitude harder than the restricted one. The repository's continuation and
arrangement-completion theorems remain reconstruction results, and combining them with
these eliminations does not produce an obstruction.

## Mystery ledger

1. **Why the order-13 orbit-matrix equation is so rich.** `B B^T = 12(I + J)` with
   constant row and column sums 12 is a tight-looking system - it forces
   `det B = +/- 12^6` - yet it has solutions of at least two structurally different
   kinds, `2` times a symmetric `2-(11,6,3)` design and the mixed-type witness above.
   *Settled by the closeout pass:* the `(2^6)` row type makes `B/2` an incidence matrix of
   a symmetric `2-(11,6,3)` design, and the mixed types are genuinely different objects,
   so the equation is a weak constraint by design. *Still open:* whether the solution set
   has a clean description. Owning successor: the tactical-decomposition abstraction
   named in the interface notes.
2. **The `f = 1` rigidity.** At `p = n + 1 = 13` the fixed structure collapses to a single
   non-incident point-line pair with no case analysis left over, which is why the case is
   exactly computable. *Settled:* this is forced by `f = 1 mod 13` colliding with the
   subplane bound `m^2 + m <= 12` and with the perspectivity order divisors 12 and 11. It
   is a coincidence of order 12 rather than a general phenomenon, and the same argument at
   other `n` gives several surviving values of `f`. No further work owed.
3. **Order 10 versus order 12 at the orbit-matrix level.** `n = 10`, `p = 11` yields 3 024
   normalized orbit matrices all of the single row-type profile `[8,1]`, while `n = 12`
   already exhibits at least two profiles. *Open:* whether the profile rigidity at
   `n = 10` reflects something about the arithmetic of `11` or is an artifact of the
   smaller dimension. Evidence gap: the `n = 12` profile census, which this wave
   abandoned. Not owned by any allocated task.
4. **Node-count scaling of the difference-set search.** Node counts grow by a factor of
   roughly 100 per step in `n` (`9.3e7` at `v = 91`, `1.1e10` at `v = 133`,

## The completion problem, stated exactly

Let `n` be the plane order, `p = n + 1` prime, and `s` a collineation of order `p`.
Wave 2A proved that `s` fixes exactly one point `P` and one line `L`, non-incident, so
the point orbits are `{P}` together with `n` orbits of size `p`, one of which is the
point set of `L`, and dually for the lines. Identify each orbit with `Z_p` by choosing a
base point and a base line, and write `D_ij` for the set of `x` in `Z_p` such that the
`x`-th point of orbit `i` lies on the base line of orbit `j`. Indexing point orbits
`0..n-1` with `0` the orbit of `L`, and line orbits `0..n-1` with `0` the pencil through
`P`, the base choices can be normalized so that

```text
D_{i,0} = {0}  for every i,        D_{0,j} = {0}  for every j.
```

Writing the plane axioms out in the group ring `Z[Z_p]` gives exactly four conditions,
and two of them are automatic under that normalization. What is left is:

- **row cover** - for each `i >= 1`, the sets `D_{i,1}, ..., D_{i,n-1}` partition
  `Z_p \ {0}`. (This is "`P` and a point off `L` lie on exactly one line".)
- **column cover** - for each `j >= 1`, the sets `D_{1,j}, ..., D_{n-1,j}` partition
  `Z_p \ {0}`. (This is "`L` and a line off the pencil meet in exactly one point".)
- **the difference condition** - for every ordered pair `(i, k)` of point-orbit indices
  in `1..n-1` and every nonzero `g`, exactly one `x` with `x` and `x - g` both nonzero
  satisfies "`x` in `D_ij` and `x - g` in `D_kj` for the same `j`".

The two cover conditions say precisely that for each nonzero `x` the assignment
`i -> the j with x in D_ij` is a **bijection** `pi_x` of `{1, ..., n-1}`. So the entire
structure is `n` permutations `pi_1, ..., pi_n` in the symmetric group on `n-1` letters,
indexed by the nonzero residues, and the difference condition becomes

> for every ordered pair `(i, k)` and every nonzero `g`, exactly one `x` with `x` and
> `x - g` nonzero has `pi_x(i) = pi_{x-g}(k)`.

Equivalently: for each nonzero `g` the `n-1` permutations `pi_{x-g}^{-1} pi_x` form a
sharply transitive set, that is, a Latin square of order `n-1`.

**This is an exact cover.** The `n(n-1)` ordered pairs of distinct nonzero residues each
claim `n-1` slots `(g, i, k)`, and there are `n(n-1)^2` slots in total, so a valid
configuration claims every slot exactly once and a repeat claim is an immediate refutation.
For `n = 12` that is 12 permutations of 11 letters filling 1 452 slots with 1 452 claims.

**The hyperoval.** `n = 12` is even, so ovals and hyperovals coincide as a case
(wave 2A). An `s`-invariant hyperoval is `{P}` together with one point orbit, and it is an
arc exactly when the corresponding row is two-to-one, i.e. when the map `x -> pi_x(m)` has
six fibres of size two for some row `m`. Those fibres are the starter of the
one-factorization of `K_14` that wave 2A extracted. So the wave-2A starter enumeration is
recovered as a projection of this model rather than being an independent ingredient.

**Normalizations**, all lossless:

1. Relabelling line orbits sets `pi_1` to the identity.
2. Conjugating by a relabelling of point orbits then moves the hyperoval row to index 0
   while preserving `pi_1 = id`.
3. The residual symmetry is exactly simultaneous conjugation `pi_x -> rho^-1 pi_x rho`
   (by any `rho` in general mode, by any `rho` fixing row 0 in hyperoval mode), so `pi_2`
   may be restricted to **one representative per conjugacy class**. In general mode the
   classes are the cycle types of `n-1` points; in hyperoval mode they are cycle types
   together with the length of the cycle containing row 0. For `n = 12` that is 56 classes
   in general mode and 139 in hyperoval mode, in place of the `11! = 39 916 800`
   permutations they represent - a reduction of the level-2 branching by a factor of about
   `3 x 10^5`. This is what makes the search feasible at all.

The classes are independent subtrees, so they are searched in parallel and reported one by
one. A run that does not exhaust globally still certifies exactly which level-2 classes
are eliminated, which is what turns a timeout into a stated boundary rather than a
non-result.

**Where Hall enters.** Choosing `pi_x` at level `x` is choosing a perfect matching of the
bipartite graph whose edges are the `(row, column)` pairs not yet excluded by the earlier
levels. `ergodis_private::hall_core` is therefore called at **every node**, on the residual
graph of unassigned rows against unused columns: a Hall-deficient set is an explicit
witness that the partial assignment cannot be completed to a permutation, and the node
dies. This is the wave's load-bearing use of the matcher, not a decoration - it is the
same primitive the wave-2A difference-set and starter certificates used, applied to the
inner loop. Rows are then branched most-constrained-first. The exact-cover bookkeeping over
the slots `(g, i, k)` is not matching-shaped and is done directly.

## Model validation

The model is validated end to end rather than argued for.

1. **`n = 4`, `p = 5`.** The search returns 2 solutions and exhausts. Feeding a solution
   back through the Python helper reconstructs an incidence structure with 21 points, 21
   lines, every line of size 5, and all 210 point pairs covered exactly once - a genuine
   projective plane of order 4, produced from the permutation data alone. Its orbit matrix
   has row sums 4, row square sums 8, pairwise dots 4 and column sums 4, exactly the
   wave-2A constraints at `n = 4`. All three of its rows are two-to-one, so `PG(2,4)`
   carries an order-5-invariant hyperoval, and the hyperoval mode also returns 2 solutions.
2. **`n = 6`, `p = 7`.** The search exhausts with **0 solutions**. This agrees with wave
   2A, where the orbit-matrix search - a different program, and independently reproduced in
   Python - also returned 0. Two structurally different arguments therefore give the same
   answer on the same case.
3. **A bug that this validation caught.** The first version of the level look-ahead
   computed the admissible `(row, column)` pairs once per level, on the assumption that two
   claims made within a level can never collide. That is false: the claims from earlier
   levels `y1` and `y2` collide exactly when `y1 + y2 = 2x`. The uncorrected search
   reported 24 spurious solutions at `n = 6`, whose orbit matrices failed the wave-2A row
   square-sum test, which is how the error surfaced. Claims are now made and checked
   incrementally; the level look-ahead survives as a sound relaxation used only for pruning.

The `n = 6` agreement is the load-bearing check. Wave 2A eliminated that case from the
orbit matrix - a `5 x 5` integer matrix equation - while wave 2B eliminates it from the
full incidence data as an exact cover on 150 slots. The two programs share no code and the
`n = 4` reconstruction shows the wave-2B model is not vacuously restrictive.

## Wave 2B mystery ledger

1. **Why the hyperoval assumption does not help.** Intuitively, forcing a row to be
   two-to-one is a strong constraint, so the hyperoval case should be easier than the
   general one. It is not: at depth 3 the hyperoval search has `2.04 x 10^9` survivors
   against `8.22 x 10^8` for the general search. *Settled by the closeout pass:* the
   hyperoval assumption shrinks the residual symmetry group from all of `S_11` to the
   stabilizer of one row, so the level-2 class count rises from 56 to 139, and the loss of
   quotient outweighs the gain in constraint at shallow depth. *Still open:* whether it
   pays off at greater depth, which is exactly what the run could not reach.
2. **The `n = 6` collapse happens only at the last level.** The survivor counts go
   `528, 1611, 30, 0` - the count still rises at depth 4 and only dies when the exact cover
   runs out of slots at the final level. This is the worst possible shape for a search,
   because no early contradiction exists to be found. *Open and important:* if the same
   shape holds at `n = 12`, no amount of pruning at shallow depth will help and the method
   is structurally wrong for this problem, not merely slow. Evidence gap: a survivor profile
   at `n = 8`-style intermediate cases is not available, since `n + 1` must be prime, so the
   only ladder rungs are `n = 4, 6, 10, 12`.
3. **The depth-3 growth rate.** Survivors at depth 3 grow by about `10^4` for each step of
   two in the order (`528`, `9 x 10^6`, `2 x 10^9`). *Open:* no model explains the exponent,
   and with only three data points none should be fitted. It does bound expectations: a
   method that must enumerate depth-3 survivors is finished at `n = 14` regardless of
   engineering.
4. **What would actually move this.** The exact cover has `1 452` slots and `1 452` claims,
   so it is perfectly tight, which is normally the regime where algebraic obstructions
   exist. The character-theoretic shadow of the model is a `12 x 12` matrix over
   `Z[zeta_13]`, with entries that are sums of distinct 13th roots of unity, satisfying
   `F F* = 12 I` and having first row and column all ones. *Open:* whether the arithmetic of
   `Z[zeta_13]` - where 2 is inert, since 2 is a primitive root modulo 13, and 3 splits into
   four primes of degree 3 - forbids such a matrix. That is an algebraic question, not a
   search, and it is the successor most likely to produce an elimination. It is not
   allocated to any task.
5. **No mystery on the negative side.** The failure to eliminate is fully explained by the
   survivor counts; there is no unexplained margin and no suggestion that a better
