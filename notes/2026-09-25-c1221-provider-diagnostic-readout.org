** DONE Fix the readout contract and failure lifetime

Use =EXECUTE= with a four-byte little-endian selector, zero handle, empty body, =ergodis-diagnostic.v1= output, and a 4096-byte maximum. Require the descriptor entry's name, format, effect, and bound to agree before the host uses it; older descriptors without the entry remain admissible. A failed operation records one current diagnostic; a successful ordinary operation clears it. Reading succeeds once and consumes it. A missing, already consumed, oversized, malformed, or failed readout becomes a typed host =diagnostic_unavailable= with original status and operation, never a guessed producer reason. Neither retrieval nor legacy refusal reads should replace the failure being retrieved. Keep conversion and JSON outside successful evaluator/checker loops.

Red-team gates: stale failure after success; another call between failure and readout; readout with insufficient capacity; forged descriptor ID/name or oversized envelope; provider failure or WASM trap during retrieval; wrong instance; non-ASCII Rel source span; verifier rejection versus record mismatch. A host helper must preserve the original status even when retrieval fails.

The public contract constants and native descriptor validator are [[file-rev:abafcee:~/src/ergodis/crates/modules/src/lib.rs][here]] and [[file-rev:abafcee:~/src/ergodis/crates/modules/src/native.rs][here]]; the browser validator is [[file-rev:9a9773a:~/src/ergodis/wasm/www/module-host.js][here]]. The ABI header, status set and rejection output rule did not change. Both validators admit older descriptors without the new selector and reject a claimed diagnostic format with the wrong name, effect, input format or 4096-byte bound. Shared native/JS descriptor cases include a valid entry, an oversized entry and a spoofed name ([[file-rev:96fa3fb:~/src/ergodis/crates/modules/tests/execution-contract.json][fixture]]). A missing or already consumed provider readout returns =STALE= with zero written bytes. An undersized readout returns =CAPACITY= with zero written bytes and leaves the saved failure available for retry. Ordinary successful provider calls clear the new slot.

** DONE Implement native and Worker/WASM host retrieval

The native helper accepts an exclusive =Provider= borrow and retrieves before returning the failure. The Worker calls it before publishing a failed checkpoint or accepting another provider call. Structured transport carries the provider envelope or a typed unavailable/host fault, including original status and operation. Success returns ordinary output unchanged.

[[file-rev:9a9773a:~/src/ergodis/crates/modules/src/native.rs][=Provider::call_with_diagnostic=]] holds one exclusive mutable borrow through the failed call and immediate selector read. Its =ProviderFailure= retains the original status and operation; a typed =DiagnosticUnavailable= says whether the contract is missing, the instance failed, the readout rejected, or the payload is invalid. Native decoding validates the complete C1220 envelope including its content ID. Existing =call= remains available for consumers that do not request diagnostics. A real legacy finite-rules provider confirms missing-readout fallback with the original =STALE= status ([[file-rev:447288a:~/src/ergodis/crates/rules-module/tests/native_load.rs][integration test]]).

[[file-rev:9a9773a:~/src/ergodis/wasm/www/module-host.js][=ModuleProvider.callWithDiagnostic=]] reads on the same WASM instance synchronously and returns the original status plus a diagnostic object or typed =diagnostic_unavailable=. The [[file-rev:9a9773a:~/src/ergodis/wasm/www/module-worker.js][Worker]] uses it for ordinary calls and checkpoint steps. A failed checkpoint carries its diagnostic into =error_detail= before publication; compatibility =error= text remains for current clients. [[file-rev:bc3369c:~/src/ergodis/wasm/www/execution-loop.js][The loop]] stops after that step. Worker transfer tests cover structured direct and checkpoint failures. The browser host checks bounded UTF-8 JSON and envelope shape synchronously; it does not recompute the =diagnostic_id= hash. The native host does. The ID is a support identifier, not verification authority; a later browser schema/rendering slice can add full client-side decoding if it uses the ID for decisions.
