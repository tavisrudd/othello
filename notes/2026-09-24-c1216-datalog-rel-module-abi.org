* DONE A: Choose the provider boundary and trust contract

Authority: [[file-rev:479668311:~/src/othello/notes/2026-09-22-c1216-datalog-rel-module-abi.md][C1216 card]]. C1205, C1213 and C1218 are complete. The starting source revisions are core =5ea22b5= and private =704ef47=; this task changes neither the native direct APIs nor public-to-private dependency direction.

Use two coarse providers under the existing =ergodis-modules= ABI v1 and public native/browser hosts. The core Datalog provider owns one admitted Boolean wire program, Demand plan and bounded workspace per instance handle. The private Rel provider owns the source bytes, std-only frontend lowering, private driver, checked result and optional transferable evidence. Rel is one provider because its execution layers, typed readout and evidence share source and workspace authority; dividing it into frontend/lowering/evaluator providers would add cross-provider identities and private serialization between stages. The public host sees only a manifest, descriptor and opaque byte buffers; the private module is built separately and the public core never imports private source.

=PREPARE= admits and stores source authority, =WORKSPACE= creates a bounded execution workspace, =EXECUTE= selects coarse readouts, and =RELEASE= follows the existing nonce-bound ownership rules. A failing ABI call writes zero bytes; a separate cold refusal readout carries a structured error after rejection. A capacity refusal must leave the resource graph valid, so callers may retry with a larger output buffer. The descriptor states the exact schema, selectors and output bounds. Unsupported schemas and selectors fail closed. No per-tuple ABI calls or provider hooks enter a hot loop.

The ordinary Rel readout returns a compact checked summary and keeps the result behind the workspace handle. Bounded relation-row and typed-value pages let a caller reconstruct it without making one large ABI output. Certificate construction, transferable evidence encoding and independent checking are separate opt-in selectors. The checker must re-admit the source and verify its own records, not trust a producer's success bit. A module's certificate bytes are compared with the native direct route on fixed inputs. An ABI success alone is not a certificate of correctness.

The agreed Datalog descriptor uses capability =finite.datalog= and the exact wire schema =finite-boolean-datalog-rules.v1=. Its v1 selectors cover ordinary evaluation, derivation/ranked/ranked-runs/ranked-round-block certificates, independent recorded checking, record replay and last refusal. The round-block selector advertises =finite-boolean-ranked-round-blocks.v1= and returns canonical bytes. The private descriptor uses capability =private.rel-evaluation= and source schema =rel-source.utf8.v1=. Its selectors cover ordinary summary, opt-in transferable evidence, offline verification, last refusal, relation-row pages and typed-value pages. Rel's =WORKSPACE= accepts the default, an explicit four-byte little-endian row bound, or a strict versioned JSON request with that bound and typed external seed rows. Only admitted external relations can receive seed rows. No bound is silently reduced.

Provider defaults must suit eager-commit WASM and small-memory hosts: use a bounded source size, conservative frontend capacities and a bounded row default rather than the native Demand default of =1 << 24=. Before allocating each Demand workspace, inspect its predicted bytes and enforce a provider workspace-reservation cap (target 64 MiB). This is not a whole-process RSS ceiling: host I/O buffers, code and other state add memory. Datalog ABI v1 fixes its row bound at 4096; Rel callers may request a different bound within the named hard limit. Capacity exhaustion returns a structured refusal; it cannot silently reduce a requested bound. Native direct APIs keep their existing defaults.

Threat cases for review: forged/stale/foreign handles, releasing a plan while a workspace is live, retry after a short output buffer, schema confusion between grounded and Datalog routes, malformed or oversized source/certificate, source or certificate substitution, empty/large input, WASM memory growth invalidating views, and panic containment at the C boundary. Run the compiled modules in the actual public host; merely compiling =wasm32= does not establish host support.

* DONE B: Implement the core Datalog provider

Owner: Luna xhigh, root design and code review. The implementation belongs in a separate public core crate using =ergodis-modules= ABI v1 and the existing Datalog admission, Demand evaluator and independent verifier. Add native and WASM ABI gates on exact result, certificate bytes, structured refusal and lifecycle. Retain the existing =ergodis-rules= module and direct Demand API.

Review found that the historical =ergodis-rules= evaluator crate itself exported the generic =ergodis_*= C names. Linking it into a second provider would collide at the symbol boundary, including in all-feature builds. The implementation therefore moves the old finite-rules adapter into =ergodis-rules-module=, keeps the evaluator in =ergodis-rules=, and retains the old Rust descriptor accessor through a shim. The old provider's descriptor and selector bytes are required to pass the pre-extraction native and WASM oracles exactly. This is an intentional module ownership change, not a change to the finite-rules protocol.

The new Datalog adapter enforces the host's 32 MiB I/O limit and its smaller advertised readout limits while serializing, before a large certificate buffer is allocated. Its round-block encoder has an exact measured-size preflight before output allocation. The evaluator uses a fixed 4096-row bound, checks the predicted aggregate live Demand workspace reservation against 64 MiB, and caps per-instance handle identities at 32. This is a workspace reservation policy, not an RSS claim. The direct =Demand= defaults and existing certificate methods remain available. Performance provenance and its limit are assessed in E.
