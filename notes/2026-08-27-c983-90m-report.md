**Lane**: `complete-ports`

## Executive result

The useful core of Ergodis is not “a coding solver” and not ownership of a new
Myhill--Nerode theorem.  It is a certified compilation discipline:

```text
domain component + admitted contexts + query profile
    -> finite exact semantic presentation
    -> verified compression passes
    -> portable evaluator + certificate + witness/provenance sidecar.
```

Every pass states the object it compresses and the equation it preserves.
Classical automata minimization, potential/weight pushing, graph finite integer
index, representative sets, semiring provenance, Pareto DP, predictive state,
and interface games become controls or backend instances.  Their prior
existence changes attribution; it does not remove the compiler SDK, artifact
format, oracle wrapper, query-profile runtime, boundary protocol, diagnostic,
or exact-to-approximate laboratory.

The hostile result is equally important: contextual congruence and abstract
minimality are cheap.  Finiteness, effective separators, useful compression,
witness lift, and repeated-query economics are the actual gates.

## What was established

### Exact common boundary

The deterministic finite core is a multi-sorted context machine with finite
reachable carriers, typed total generator actions, finite observations, a
domain lift, and an independently replayable refinement transcript.  Its
stable observation refinement is the largest generator-compatible equivalence
inside the observation fibres, hence the coarsest exact quotient of that
presentation.  A strict-refinement count gives a finite separator-height bound.

The more general compiler theorem is factorization, not quotienting.  If an
encoding commutes with every typed constructor and every requested observation
factors through it, all generated contexts are exact by induction.  A Kleisli
version covers deterministic, relational, probabilistic, and weighted
branching once the semantic effect and terminal evaluator are explicit.
Alternating ownership and equilibria require a game/interface backend rather
than an untyped min/max shortcut.

This is a genuinely broader organization, but not a novelty claim for the
individual rows.

### Compression mechanisms kept separate

1. Contextual quotient of individual states.
2. Potential/gauge normalization with a carried cocycle.
3. Representative-family reduction of competing partial solutions.
4. Circuit/provenance factorization of shared derivations.
5. Approximate clustering under a declared behavioral error law.

Combining them is allowed only when their preservation contracts compose.
Value-state bytes, transition/circuit bytes, potential payload, certificate
bytes, and witness/provenance bytes must be reported separately.

## Two admitted noncoding exemplars

### A. Bounded tropical weighted-tree evaluator

Compile reachable truncated valuation vectors of a finite min-plus weighted
tree automaton, then minimize by final observation and retain distinguishing
tree contexts plus optimal-run backpointers.  A concrete radius-4, three-state
fixture has 13 reachable vectors, four initial observation fibres, and six
contextual classes after one refinement round.  It includes a height-one
distinguishing context, so it tests real contextual refinement rather than
output deduplication.

### B. Symmetric finite resource batches

Compile a job batch as a min-plus relation between sorted load profiles,
compose batches exactly, minimize for a bounded future/query grammar, and
reconstruct an assignment.  Exhaustive cheap tests show compression beyond
machine permutation symmetry: for three machines, cap 5, jobs `{1,2,3}`, and
horizon 2, 56 sorted profiles give 42 absolute and 31 potential-normalized
response classes.

The cheap test also caught the adapter's main trap: a job has several possible
successors, so choosing one continuation-blind argmin is unsound.  The exact
adapter needs batch relations or determinized residual response functions,
with remaining horizon represented in the type/sort.

## New terrain exposed

- **Legacy exact-solver wrapping**: learn a deterministic finite observational
  machine from constructors, membership queries, and exact counterexamples.
- **Decision-diagram/OR integration**: exact DDs already compile DP state graphs,
  merge equivalent states, and integrate with CP/IP/branch-and-bound.  Ergodis
  must add query-relative certified minimization, typed compression passes,
  black-box wrapping, or cross-domain artifacts, and benchmark DD tooling—not
  rely on a CP-SAT comparison alone.
- **Boundaried graph/network optimization**: absorb graph Nerode, finite
  integer index, and rank-based families as separate backends; target generated
  quantitative adapters and exact solutions.
- **Distributed boundary protocols**: quotient class count is the exact
  one-way structural message alphabet; potentials and witnesses are explicit
  extra payloads.
- **Exact mergeable summaries**: compile finite ordered-segment semantics into
  certified `summarize/merge/query` states for parallel streaming and
  distributed analytics.  List homomorphisms and mergeable-summary algorithms
  are classical controls; order, commutativity, and approximation guarantees
  remain explicit.
- **Max-plus discrete-event planning**: realization, reachability, and
  observability are established control theory.  Ergodis can instead compile
  bounded deadline/resource query profiles for manufacturing, transport,
  synchronization, and queueing components, retaining schedules and a finite
  verifier without claiming an unbounded minimal realization.
- **Multi-resource repair and operations**: bounded Pareto antichains compose
  exactly, but hard-cap scalarization is terminal and not generally a semiring
  homomorphism.  A concrete overflow counterexample and exhaustive small-box
  algebra check now guard this boundary.
- **Robust planning and component compatibility**: alternating action ownership
  and strategy witnesses open fault/disturbance planning, protocol control, and
  interface compatibility.  Cooperative and adversarial fixtures must produce
  different semantics when ownership matters.
- **Proof-carrying finite analysis**: minimize an existing finite abstract
  interpreter or protocol monitor for selected assertions/cost queries, then
  ship dense transformers and an independently replayable certificate.  The
  original abstraction retains responsibility for concrete soundness and
  counterexample lifting.
- **Exact-to-learned realization**: the exact compiler supplies response
  coordinates, transitions, separators, counterexamples, rollout oracle, and
  fallback.  Linear/PSR, MLP, GRU, and Mamba-style updates compete under the
  same latent budget; Mamba is one vehicle, not the premise.

## Red-team findings

1. Coordinate-complete unrestricted contexts recover a kernel entrywise, so
   they permit no semantic quotient beyond gauge or representation factoring.
2. Congruence does not imply finite index, computability, or compression.
3. Equality-complete separators need not be projectively complete.
4. Finite sampled contexts lower-bound contextual distance; they do not certify
   an all-context approximation.
5. Literal argmin identity can destroy a value quotient; witnesses need a
   separate lift or transient provenance.
6. Hard-cap Pareto scalarization cannot generally be pushed through
   composition because a locally cheapest point may overflow later.
7. Branch ownership cannot be erased into an untyped aggregate without
   changing robust/game semantics.
8. A sampled equivalence oracle certifies only its sample, not a finite target
   universe.
9. A minimal one-directional streaming state need not be an exact summary for
   independently processed segments; arbitrary ordered merging requires a
   two-sided congruence, and partition reordering requires commutativity or an
   order protocol.

The robust-interface regression is deliberately tiny and decisive.  With
`a,d in {0,1}` and cost `1[a != d]`, controller-first play has
`min_a max_d = 1`, while observed-disturbance-first play has
`max_d min_a = 0`.  The payoff table is the same; only move order and
information differ.  The witnesses are also different types: one committed
action versus a contingent policy.  This catches an ownership-erasing generic
relation backend before it reaches a real protocol or fault-planning adapter.

## Application framing and acceptance

The first meaningful release is a toolchain, not a theorem announcement:

1. explicit finite compiler and independent verifier;
2. weighted-tree and resource-batch adapters behind one artifact;
3. schema-hashed query profiles with monotone refinement;
4. potential specialization with projective certificates;
5. oracle front end wrapping a legacy exact solver;
6. graph/network and robust-interface stretch adapters;
7. exact-to-approximate benchmark laboratory.

For every adapter report raw states, transitions, quotient states, all byte
categories, compile time, exact-oracle agreement, witness validity, and
repeated-query break-even.  The architecture passes only if unrelated domains
share the minimizer/verifier without domain branches and the artifact yields a
measured size, reuse, protocol, or certification gain.
