** DONE Test a taxonomy against the inventory

| Class | Representative fit | Exception or ambiguity |
|-
| Malformed input | Parser =REL01xx/02xx=, invalid wire framing, noncanonical certificate encoding. | Grounded =Source= also covers some well-formed semantic violations. |
| Well-formed but outside supported fragment | =REL0301=, =REL0504=, ABI =UNSUPPORTED=. | A provider's =UNSUPPORTED= operation is protocol capability, not source-language fragment. |
| Budget refusal | C1206 =BudgetRefusal=, route =REL0503=, checker =Budget=. | Separate caller-movable knob, fixed implementation policy, unknown OS reservation limit and stopped/incomplete work. A zero unknown limit is false information. |
| Certificate or record rejection | Derivation/ranked/support/weighted checker, =ReplayError::Record=, offline =Rejected=. | A checker disagreement or valid certificate with mismatched stored record is a trust incident; its UI should not suggest editing source syntax. |
| Internal invariant | Two checkers disagree, source/record reconstruction disagrees, impossible dictionary ID. | These must not be silently rendered as a value or a generic user =INVALID=. |
| Host/environment | OS reservation, file I/O, WASM load/worker timeout, provider panic. | Status 1 and generic =Rejected:= currently obscure this class. |

The six classes need two orthogonal states: *concurrency/identity conflict* (=STALE/BUSY=, repository revision/fence/request conflict) and *check lifecycle* (not checked, running, incomplete, verified, rejected). An ordinary exact negative answer or a valid obstruction is an outcome, not an error. A user stop/cancel is a terminal operation state, not a malformed input. These do not fit honestly in the six error classes.

** DONE Resolve audit design questions

The [[file:2026-09-25-c1207-error-model-design.org][adopted decision]] sets a schema-major stability promise for new codes, nonzero exit for a refused requested CLI operation, and a common versioned provider diagnostic readout with typed diagnostic-unavailable fallback during migration. A status-only legacy provider may exist during compatibility but must not yield an invented reason. Unknown dictionary-ID reachability remains unproved; the [[file-rev:c36b5073a:~/src/othello/notes/2026-09-21-c1208-c1204-findings-triage-report.md][closed C1208 triage]] assigned the observed ="?"= loss to this audit, and repair belongs to implementation candidate 1.
