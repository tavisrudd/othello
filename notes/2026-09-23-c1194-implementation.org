* Implementation order and interfaces

1. Contract. Add a distinct weighted prepared source. Its value table maps
   every domain ID to an integer payload or an explicit noninteger tag. A
   weighted relation has a key arity and one cost column outside the key;
   structural relations are frozen inputs with zero relation cost. Rules
   contain resolved atoms plus a bounded list of literal/body-field offset
   addends; each weighted body factor's cost contributes exactly once.
   Admission checks shape, source budgets, canonical variable binding,
   finite nonnegative fact costs and addend references. Duplicate weighted
   facts take the minimum. Encoding includes the typed table and rule
   addends, is domain separated, and decodes only canonical bytes. Define a
   canonical sorted value result and a separate fixed-size source/result
   binding envelope. This module must not change Boolean bytes or semantics.
2. Verifier. Given *serialized* source/result/envelope, re-admit source,
   validate canonical result and binding, then independently mark finite
   rows supported by exact-cost source facts and rule matches on already
   marked rows. After every listed row is marked, independently test all
   input facts and all rule matches for closure. Reject exhaustion,
   overflow, unsupported zero cycles, lower omitted costs, and tampering.
   Issue a verification record only after both passes. The envelope alone is
   a claim. The checker belongs in =ergodis-verify= and does not call the
   weighted producer or its compiled joins.
3. Evaluator. Prepare a separate weighted relaxation kernel in
   =ergodis-rules=. Share only cold admission/join/index shape code whose
   extraction preserves measured Boolean code shape; otherwise retain
   bounded cold duplication. Stable row IDs index flat tuple and parallel
   best-cost columns; joins follow every improvement, including improved
   existing keys. A source-only rule has a seed pass. Queues and join frames
   are presized; overflow or work exhaustion refuses. The evaluator has no
   certificate flag, hash, witness/rank column or proof serialization.
4. Rel. Admit term-level integer =+= and normalize each weighted recursive
   head-cost expression to every weighted body cost once plus nonnegative
   literal and bound typed-field addends. Reject subtraction,
   multiplication, repeated/missing cost variables, negative/noninteger
   costs, and cost-dependent negation/comparison with =REL05xx= diagnostics.
   The private route maps the typed dictionary and per-layer carrier to the
   prepared source. Earlier structural layers freeze before entry.
5. Independent reference and acceptance. Evaluate min-plus fixed point
   naively from the admitted AST, without reading RIR or weighted plan.
   Exercise source SSSP and component labels, duplicate and improved keys,
   zero/positive cycles, 3/4-body joins, sentinels, malformed bytes,
   mixed layers and seeded differential cases. Check ordinary result bytes
   are identical with and without an opt-in check. Run native and WASM
   compile/parity gates and old-path A/B; profile the new weighted kernel
   and the verifier separately. Close with the required arithmetic coverage
   and Mystery ledger.

* Rel source pattern for the first weighted route

Use the existing aggregate surface =d = min[c: candidate(k,c)]= as the
explicit declaration that =d= is the cost column of =dist(k,d)=. The
candidate relation may have several rules; one rule may bind its cost by a
single defining equality =c = a + w + literal=, where =a= is the cost
column of a weighted body relation and =w= is an integer field of a frozen
structural body relation. A base candidate may bind =c= directly from a
structural input field. The compiler fuses this candidate/min pair into
weighted rules for =dist=; it never materializes the full candidate-cost
relation. The pair is admitted only when the candidate relation has no other
consumer, every candidate rule has one cost-defining expression in the
normal form, and the =min= groups by all remaining candidate columns in
the same order. Otherwise emit a =REL05xx= refusal with the offending term.

For example, semantic Rel shape (exact binder spelling belongs to the
parser's existing grammar):

  =candidate(v,c) <- seed(v,c) ; dist(u,a), edge(u,v,w), c=a+w=
  =dist(v,d) <- d=min[c: candidate(v,c)]=.

This special defining equality is *cost construction*, not a recursive
Boolean filter. Other comparisons involving a changing cost remain outside
the first fragment. An =edge= weight is a typed key field and contributes
as an offset; =dist= contributes its current minimum automatically. This
pattern avoids enumerating ever longer cyclic candidate paths while giving
the source an explicit =min= that selects the carrier. The private lowering
must preserve the existing nonrecursive boundary aggregate behavior for
other uses of =min=.

Recognition runs before the ordinary stratifier rejects a cycle through an
aggregate. It accepts only the pattern above, removes that candidate/min
boundary from the Boolean dependency graph, and compiles the candidate
rules directly as weighted rules headed by the min relation. The candidate
relation is not observable elsewhere; source facts on it become weighted
seed facts. Several mutually recursive min relations may share one weighted
component. A Boolean relation derived in that component is refused. After
the weighted closure, the driver interns finite costs into its existing
typed dictionary for downstream readout/layers; cost is never a key-domain
digit inside the weighted kernel. The prepared source binds the dictionary
at entry, and a downstream source binds the enlarged dictionary separately.

* Fermi and red-team gates before implementation

- Hot storage at capacity =R=: approximately 16 bytes per row beyond tuple
  and indexes (cost, two queue slots, epoch). One million rows reserves
  roughly 16 MB on paper; Unix pages commit lazily, while other targets may
  commit eagerly. This is a capacity estimate, not an RSS measurement.
- Off-path certification cost should be one cold API dispatch and zero hot
  operations; the intended generated weighted loop and normal result bytes
  are identical. ThinLTO may defeat source-level isolation, so disassembly
  and an interleaved old/new evaluator A/B are mandatory.
- Checked total cost is evaluator plus checker. A value-only result makes
  checker support reconstruction potentially expensive, especially on
  dense zero-cost joins; measure its marks, matches, instructions, time and
  RSS separately. A later rank sidecar is allowed only if that measurement
  warrants it and never changes the normal evaluator/result.
- An overflow in even a dominated candidate is a deliberate refusal in
  the first contract. A test must show this exact conservative behavior;
  no saturated =INF= may silently certify an unbounded answer. Producer and
  checker must compute each actual match's sum before a dominance test so
  opting into checking does not change the refusal result.
- Source-bound prepared identity is not full Rel text authority. The
  existing layer/source provenance task owns that separate boundary.
