** DONE Propose vocabulary and ownership

*Recommendation:* retain small typed errors at their producing layer. Convert them on a cold failure path into one versioned =Diagnostic= envelope at the outermost domain/host boundary. Every conversion must preserve the original stable reason and append context; it must not replace a typed cause with =Debug= or arbitrary text. This avoids forcing a public core crate to depend on private Rel concepts or browser concerns. A single crate-wide error enum is simpler to discover initially but grows a cross-domain dependency and forces public releases to carry private meanings; unrelated local enums without a common conversion rule preserve the current drift.

Proposed envelope fields: =schema=, =code=, =class=, =severity=, =operation=, =message_key=, typed =subject= (kind/id/name when safe), ordered =context= frames (layer, relation, rule, record, source span), optional =budget=, optional =trust=, optional typed =cause=, and optional support =diagnostic_id=. The envelope is plain bounded data; prose is derived later. The source-local error remains authoritative. An outer frame must not invent a source span: [[file-rev:8045e30:~/src/ergodis-private/crates/rel-module/src/lib.rs][Rel's provider currently labels layer numbers as spans]], which the conversion rule should prohibit. Use source byte offsets plus a source identity, with display line/column computed cold. Never put unbounded source snippets or arbitrary =Debug= text in the stable fields.

*Codes:* keep existing =REL0001=…=REL0505= stable for their current specific meanings; add product-wide namespaced codes for core admission, checker, record, provider, runtime and host. Code meaning is stable within a published schema major version; human wording, help and localization may improve without changing code. A code is not the same as C ABI status: status is a coarse transport category and stays 0–5. An extension of =REL= numbering to the whole product would mislabel non-Rel failures; no stable codes would prevent reliable tooling and saved receipt interpretation. Reserve =internal= codes for invariant violations and checker disagreement, never map these to ordinary malformed-input codes.

** DONE Propose structured refusals and data/rendering split

Use C1206's budget fields: =bound=, =object=, =observed=, =unit=, optional =limit=, optional =round=, optional =knob=. Add explicit =limit_source= (=caller_setting=, =fixed_policy=, =environment_unknown=) and =retry= (=with_setting=, =with_smaller_input=, =after_resource_change=, =not_recommended=, =unknown=), derived from the producer's knowledge rather than guessed by a renderer. Preserve =None= for unknown limits. Widen numbers before projection when the producer knows =u64=; a saturated projection must say “at least” rather than falsely give an exact count. A budget refusal differs from completed work with a negative result and from an incomplete check. The latter gets an explicit operation outcome with completed scope and remaining obligation.

Serialize the same envelope for tools, receipts and provider readout as JSON with a schema version and bounded size; provide a human renderer in terminal and browser. For a source error, the default human form should show code, action-oriented sentence, source excerpt/primary caret, relevant secondary label, observed versus expected and a concrete next action. The frontend already supplies most of this on an error-only path [[file-rev:8045e30:~/src/ergodis-private/crates/rel-frontend/src/diagnostic.rs][here]]; its semantic arity counts should survive rendering. Machine JSON retains exact byte spans even if excerpts are truncated or not renderable. The renderer should escape control characters and cap source text. A successful parse/evaluation must not allocate or call formatting code for diagnostics. Error-only contextual reparse is permitted only after the primary rejection is fixed; it cannot change admission, run the program or create a new proof claim.

The requested [[file-rev:bdeac37:~/src/iidy-hs/src/Iidy/Yaml/Errors/Enhanced.hs][iidy-hs quality reference]] keeps issue-specific data such as expected/found type, source location, available names, suggestions and optional help; [[file-rev:bdeac37:~/src/iidy-hs/src/Iidy/Yaml/Errors/Ids.hs][its ID registry]] groups numeric categories; [[file-rev:bdeac37:~/src/iidy-hs/src/Iidy/Yaml/Errors/Display.hs][its display layer]] adds file:line:column, source caret, guidance, examples and color/TTY handling. These are useful acceptance criteria for Rel alongside a Rust-style labelled diagnostic: a reviewer should see the wrong token or name, what was expected and found, the relevant declaration, and one actionable repair. Ergodis should derive expected/found from typed producer fields rather than recovering them from message substrings. Audit fixture =REL0402= fails the numeric and specific-secondary-label criteria today, while =REL0204= already shows a useful caret and repair hint.

For CLI behavior, recommend one explicit contract: a requested program/check that is refused or rejected emits the versioned JSON envelope on stdout in =--json= mode and a human diagnostic on stderr by default, with nonzero exit. A successful negative mathematical answer remains exit 0 with an ordinary result. Benchmark receipts may still record =ok:false= for a measured refusal, but the command's exit policy must be documented separately so a harness can distinguish a deliberately measured refusal from an operational failure. A compatibility window can retain current =rel-lower= JSON/exit behavior under its existing schema while adding a new opt-in contract before migration.

** DONE Propose trust and lifecycle presentation

The trust section should identify =claim_kind= (certificate, checker-issued record, offline bundle evidence), source/record identity digest, checker identity when relevant, the first failed field or relation/row and =verification_scope=. Distinguish: (1) malformed certificate bytes, (2) a well-formed certificate rejected against a source, (3) stored record differs from fresh checker-issued record, (4) two checkers disagree, (5) no checker run yet. Cases 3 and 4 warrant “verification failed” with evidence export and a stable diagnostic ID; they are not edit-your-source advice. The checker's typed rejection must remain nested. C1205's source-bound layer records are an appropriate context frame; the evidence format itself should not copy a UI string.

Use an explicit verification state machine in browser and saved records: =not_checked= → =checking= → =verified(scope)=, =rejected(reason)= or =incomplete(scope, reason)=. Opening a saved record resets *current* verification to =not_checked=; a historical report is shown as a historical claim, not inherited authority. The current [[file-rev:8045e30:~/src/ergodis-private/analysis/campaign-console/workspace.js][bundle workspace]] already resets the selected evidence and shows four check outcomes. Keep that behavior and avoid a blanket =Rejected:= prefix for worker, I/O and timeout errors. In application views, show a concise action/status near the affected operation, with the bound/first failed object/verification scope visible without opening a collapse panel; put raw IDs and machine JSON below the main explanation. Avoid implementation vocabulary in normal flow while preserving a copyable technical detail for support.

** DONE Propose ABI/WASM migration and performance constraints

Keep C ABI v1's coarse status and zero output bytes on rejection [[file-rev:2119cbe:~/src/ergodis/crates/modules/src/lib.rs][as contracted]]. Standardize a discoverable, bounded =last-diagnostic= readout in the provider descriptor and a host helper that immediately fetches it after a non-OK call *on the same instance*, preserving the original status if the readout itself fails. Datalog and Rel already have incompatible =last-refusal= shapes; migrate them to one envelope on a versioned readout, retaining old selectors during compatibility. If the status or provider is too broken to supply detail, the host emits a typed =diagnostic_unavailable= with status and operation, never an invented user reason. The second call races only if hosts violate the existing exclusive-instance call contract; native and Worker hosts should enforce serialization. A future ABI revision could return an error handle/payload atomically, but that is dearer and unnecessary for the first migration. WASM JS exceptions/worker transport should carry structured objects for host failures and preserve provider diagnostic data, instead of =String(error)= only.

All envelope creation, source reparse, JSON and human formatting occur after a failing predicate, outside allocation-free parser/evaluator/checker loops. Keep compact =Copy= failure records and cold dispatch. A code change to a hot loop still requires the performance contract's allocation, call-free, exact-result and A/B gates. Schema conversion tests should include native and WASM plus non-ASCII source spans; they do not by themselves establish macOS, Windows or ARM native support.

** WAIT Decide design choices with Tavis

1. *Model/codes:* approve per-layer typed errors plus lossless cold conversion and product-wide namespaced codes, with current =REL= IDs preserved? Alternative: one cross-crate enum is simpler to enumerate but creates public/private coupling; no common envelope leaves current losses.
2. *CLI contract:* approve nonzero process exit for a refused requested operation, with =--json= stdout and default human stderr, while versioning/migrating the current =rel-lower= receipt? Alternative: keep exit 0 for data-level refusals and require every caller to inspect =ok=, which is compatible but easy to misuse.
3. *Provider boundary:* approve a standard versioned =last-diagnostic= readout plus immediate host retrieval under ABI v1? Alternative: design ABI v2 atomic error payload now, which avoids a second call but expands the migration surface.
4. *Trust/UI:* approve the explicit verification states and “verification failed” treatment for record mismatch/checker disagreement, with first failed object and scope visible? Alternative: retain current per-view labels, which is cheaper initially but preserves ambiguity.
