# C985 QDistSAT LP1768 distance bounds

**Lane:** `complete-ports`

**Date:** 2026-09-01

## Result

Ergodis narrows the two CSS directions of the official QDistSAT
`LP_1768_224_?` matrices and proves them coordinate-equivalent:

\[
22 \le d_X=d_Z \le 24.
\]

Consequently the supplied matrices define a `[[1768,224,d]]` CSS code with
`22 <= d <= 24`. The official QDistSAT table retained only approximately
`8 <= d <= 230` for this instance.

The 2026-09-02 cross-direction admission in
`notes/2026-09-02-c985-lp1768-cross-direction-equivalence.md` transports the
physical row space and physical-plus-logical observable row space under one
exactly checked 1,768-coordinate bijection. Thus the two historical searches
below independently established the same lower bound; only one direction is
needed for any future radius-22 exhaustion.

| direction | exact miss through | shards | exact candidates | summed preparation (s) | summed exact search (s) | replayed upper bound | BP+OSD (s) |
|---|---:|---:|---:|---:|---:|---:|---:|
| X (`Hz/Gx`) | 21 | 32 | 133,615,602,821 | 1.205442 | 1,424.727605 | 24 | 0.686124 |
| Z (`Hx/Gz`) | 21 | 32 | 129,430,983,577 | 1.171797 | 1,474.583761 | 24 | 0.727829 |

The exact searches enumerate connected supports through weight 20. A
separately verified all-ones row-space functional proves that every kernel
word has even weight, so the absence of nontrivial words through weight 20
also excludes weight 21. This establishes the lower bound 22. The public
solver validates the functional directly against every coordinate column
before normalizing the requested odd radius down to 20.

Each direction is a deterministic 32-shard cover.  The independent shard
ledger checks compatible input, executable, kernel, artifact, radius, and
partition identities; exactly one record for every shard; every anchor
frontier; and the additive/xor branch checksums before emitting
`complete-compatible-cover`.  Both coverage manifests replay byte-identically.
The search times are sums of per-process shard timers, not a multiround
performance comparison; the Z run overlapped separate diagnostic work.

The upper bounds come from the native BP+OSD spike, not from exhaustion.
Each run decodes all 224 logical target syndromes at iteration budgets
`1,8,64,300` with exhaustive OSD order 10. All 896 returned candidates
satisfy their target syndrome and replay independently against the sparse
physical and logical rows. The best witnesses are:

- X, target 112:
  `[521,544,545,547,550,571,587,589,613,614,620,623,624,642,645,646,650,669,736,738,740,745,761,768]`;
- Z, target 214:
  `[105,128,129,131,134,155,379,381,405,406,412,415,624,642,645,646,650,669,1152,1154,1156,1161,1177,1184]`.

These are one-round certificate-generation timings, not multiround
performance estimates. The mathematical bounds do not depend on the timing
comparison.

## Scope and next closure gate

The lower bound trusts the public connected-support exhaustion, its validated
parity functional, and the independent shard-coverage ledger. The Python
checker replays positive witnesses and rejects incomplete or shard-local exact
records, but it is not a second implementation of the 263.0-billion-candidate
radius-20 negative search.
BP+OSD supplies only a checked upper bound and has no proof authority for the
lower bound.

The remaining exact gap is weight 22. A complete miss through requested radius
23 would prove `d_X=d_Z=24`; any hit instead certifies distance 22. Before
paying the roughly order-of-magnitude radius increase, profile equivalent
independent-check presentations and stronger syndrome lower bounds. The
measured X/Z asymmetry makes a blanket projection from either direction
unreliable.

## Post-certificate sharpening

The symmetry branch is now closed for the supplied sparse presentations.
Nauty independently computes an automorphism group of order 52 with one
generator in each physical Tanner graph. Its coordinate orbits are exactly
the 34 length-52 blocks already certified by Ergodis. A broader exact probe of
lifted block reflections, both offset orientations, and block-dependent cyclic
shears also found no row-space-preserving reduction. No probe code remains in
the importer.

Commit `8eab39805` instead strengthens the exact syndrome search at no hot-loop
instruction cost. During colossal compilation only, independent checks are
ordered by increasing conflict degree. The existing lowest-set-bit branch and
greedy packing operations therefore see a stronger fixed order without a new
field, lookup, branch, allocation, or recursive path in the solver. On the X
radius-14 control this visits 109,046,916 rather than 141,949,946 candidates,
a 1.302x work reduction. Seven interleaved counter pairs give:

| mode | cycles | instructions | branches | search wall |
|---|---:|---:|---:|---:|
| 1 thread | 1.065x (`t=3.07`) | 1.229x | 1.175x | 1.062x (`t=2.92`) |
| 12 threads | 1.083x (`t=21.30`) | 1.234x | 1.180x | 1.036x (`t=4.73`) |

Ratios are baseline/candidate. Branch misses increase by 38.6% at one thread
and 35.0% at twelve, but the state and instruction reductions dominate. The
first ungated version was correctly rejected because it made BB288 visit
1.605x as many states and lose 42--71% wall time. The admitted version uses
the existing colossal shape boundary (`n > 1536` or rank above 704). BB288's
hot instruction and branch counts are consequently identical; seven paired
controls show no small-solve regression, with cycles favoring the admitted
build by 1.047x at one thread and 1.035x at twelve.

The raw 56-run counter ledger is
`ergodis-private/evidence/c985-lp1768-conflict-order-ab.tsv`, SHA-256
`6084aae76a3cc3097a44ea1a8e67c5e8a290c1fd80dd2fd867015aa9609d2b66`.
The solve loop remains allocation-free in the measured single- and
parallel-worker tests. Because completion-filter keys encode the reordered
syndrome basis, colossal artifact version 2 rejects version-1 caches before
payload use; this cache-format bump is a correctness requirement, not merely
invalidation hygiene.

## Equivalent-presentation autotuning

The next compiler gate is also positive. Any independent basis of the physical
row space defines the same zero-syndrome predicate, but its static order changes
the fail-first traversal. Commits `29fbb4dbf` and `bb7e5d646` add deterministic
source-bound presentation seeds and optional bounded shallow autotuning. The
selected seed persists in the compiled artifact and shard identity; autotuning
is rejected inside a shard invocation, so one artifact is selected once and
then replayed across the complete cover.

Sixteen radius-14 probes select seed 2 for X and seed 14 for Z. At radius-20
shard zero, X candidates fall `4,280,955,058 -> 3,576,297,029` (1.1970x) and Z
falls `4,268,847,189 -> 3,742,874,647` (1.1405x). Instructions improve 1.1708x
and 1.1307x. X cycles improve 1.0673x (`t=39.75`); its three-pair wall result
is unresolved. Z cycle/wall points are also unresolved after five pairs. Both
directions increase branch misses, so state reduction cannot be treated as a
uniform wall-time ratio.

Saved-binary controls against pre-feature commit `ce182fe0b` preserve the
default presentation's exact 109,046,916 radius-14 candidates and essentially
identical instructions. Current/default cycles improve 0.6% at 1T and 1.6% at
12T; no default-path regression is present. Sixteen-probe X peak RSS is 55,696
KiB versus 30,552 KiB default because the tuner retains the best compiled
candidate while testing one challenger. It never retains the full seed bank.
