# C1038: negative-control benchmark tier for ergodis

**Lane**: `complete-ports`
**Date**: 2026-09-02
**Status**: complete; uncommitted, left in the working tree for review.

Goal: replace the assertion "ergodis is not a general constraint-programming
replacement" with a measured frontier — a predeclared classifier of the instance
shapes ergodis compiles today, a prediction table fixed before any run, and
paired measurements on both sides of that frontier, with losses reported as
first-class rows and as candidates for absorption.

Abbreviations expanded on first use. CP-SAT is the constraint-programming
Boolean satisfiability solver of Google OR-Tools. LP is linear programming. DP
is dynamic programming. RSS is resident set size.

The second change is a real weakening of the predeclaration: the sizes that were
measured are not the sizes first written down. It is recorded here rather than
concealed, and the directions — the thing the gate is about — were never edited

The ergodis replay is independent of the solve: it re-adds the selected weights
and compares with the target, or re-adds the chosen loads, checks every capacity
and checks that each chosen load vector is genuinely an option of its demand. It
reads neither the compiled plan nor the DP state. CP-SAT emits no proof log in
this harness, so its optimality claims on L2, W2 and W3 and its feasibility
verdict on L3 carry no artifact a third party can replay; on L3, where ergodis
declines and CP-SAT answers, the control's answer is the only one available and
it is uncertified. "Exact agreement" in the tables means two independently
written models returned the same number, which is the strongest cross-check
these rows have.

## 4. The misprediction

L1 was predicted to lose and won by 3.83x. The prediction assumed a DP width
near one million was already past the crossover. It is not: a single equality row
over sixty generic weights gives CP-SAT a weak linear relaxation and almost no
propagation, so it searches, while the compiled DP performs a fixed 1.9 x 10^7
transitions and finishes in 31 ms.

The classifier's deciding test was not wrong about the shape. The state does
scale with the numeric magnitude of the data, and L3 — the same shape one
magnitude out — is declined outright by the kernel. What the test does not do is
say where the resulting cost crosses the control's. L1 and L3 bracket that
crossover: for this shape the frontier is a magnitude threshold somewhere between
a compiled width of 10^6 and one of 4 x 10^6. The defect is the classifier's
resolution, not its verdict, and the row is reported rather than moved.

The named absorption mechanism for this shape is residue-class splitting of the
sum axis or a meet-in-the-middle split of the item set. Both are already used in
other kernels of the crate and neither is present in the bounded subset-sum
compiler. L2's mechanism is a dual bound on the compiled model — a Lagrangian or
surrogate relaxation of the capacity rows — used to prune frontier states; that
is the structural piece the frontier search currently lacks and it is what makes
CP-SAT four orders of magnitude faster there.

## 7. What was skipped, and what this does not claim

- **HiGHS was not used.** The classifier named it as an available control, but
  every row reduces to an exact feasibility or maximum-cardinality question that
  CP-SAT answers directly and exactly, and adding a second control would have
  doubled the cells without changing any verdict. The task's instruction not to
  add a new solver dependency was honoured; only OR-Tools was installed.
- **No random CNF row.** The crate's satisfiability module builds structured
  refutation certificates for multipartite colouring rather than accepting a
  general CNF, so a random-3-SAT row could not be run on the ergodis side at all.
  A row neither side can run is not a measurement; the shape is left in the
  classifier under N1 with its absorption mechanism named.
- **No arbitrary-side-constraint scheduling row.** Encoding pairwise
  incompatibilities would have required expanding the families by hand, which
  measures the encoding rather than the compiler. L2 exercises the same
  not-yet-compiled frontier — state that grows with the data rather than the
  structure — with no hand encoding.
- **Three rounds, not seven.** L2 costs 137 s per ergodis sample, so seven
  rounds would have exceeded the cell budget. Three rounds is the corrected
  protocol's minimum, already used for the seconds-scale rows elsewhere in
  `BENCHMARKS.md`. Cheap rows could have taken more rounds; they were run at
  three for uniformity.
- **`retain-bin.sh` was not used, and this is a tooling gap to report.** That
  script accepts `--bin` only; it has no path for a Cargo example, and the
  ergodis side of this tier is an example rather than a binary, since the task
  forbade edits under `src/`. The runner therefore records the built
  executable's SHA-256 and byte count directly in the evidence file, which
  provides the same identification, but it does not retain a hashed copy in the
  cache for a future A/B against a changed implementation. Extending
  `retain-bin.sh` with `--example` is a small, separate change.
- **`cargo test --all-features` was not run.** Nothing under `src/` was touched,
  so no library behaviour changed. `cargo fmt --check` and
  `cargo clippy --release --example negative_control_tier -- -D warnings` both
  pass on the new example.
- **No warm profile.** Every row here is a cold, single-solve comparison, which
  is the profile in which construction and compilation costs are visible. Warm
  batching would have favoured the side with the cheaper per-solve cost and
  obscured the compile-time question the tier is about.

This tier does not claim a general solver comparison, a win on any instance
outside the six measured, or that the classifier is complete. The classifier is a
description of what the software compiles today, and section 2 of it names, for
every shape it does not yet reach, the mechanism that would absorb that shape.
Nothing here is evidence about the relative merits of dynamic programming and
conflict-driven search in general.

## 8. Mystery ledger

- **Settled by this task.** Whether a predeclared classifier can be operated at
  all without post-hoc editing: it can, with the one honest caveat that instance
  sizes had to be recalibrated for measurability, disclosed in section 1.
- **Settled by this task.** Whether CP-SAT's advantage on the scheduler frontier
  is search or bounding: on L2, CP-SAT returns the exact optimum in 9 ms against
  137 s, and the mechanism it has and the frontier search does not is a dual
  bound on the capacity rows. That names a concrete, sized import.
- **Open: where the subset-sum crossover actually falls.** L1 at width 1.9 x 10^7
  transitions wins by 4x; L3 at four times the width is declined by the kernel's
  compiled cap. The crossover against CP-SAT is somewhere between, and no row
  measures it. A width sweep between the two would turn a bracketing into a
  published phase transition, which is what the source memo asked for. This is
  the highest-value cheap successor to this task.
- **Open: why W3's margin is only 2.34x.** Every other compiles-today row wins by
  18x or more. W3 has 4,000 demands over six types, exactly the repeated-interface
  shape the Azure LRC row wins on by 160x, yet ergodis spends 1.27 s and 172
  million transitions. The type quotient that makes the Azure row fast does not
  appear to be applied here. Either the scheduler does not quotient identical
  demand types the way the counted Azure model does, or this instance defeats it
  for a reason not yet identified. That is an unexplained gap in a kernel the
  document already claims, and it is worth a bounded look before the tier is
  presented anywhere.
- **Not a mystery.** L2's 15,030x loss and L3's refusal are exactly what the
  classifier said would happen, for the reason it gave.
