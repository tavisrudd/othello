* Old/new mapping and caller obligations

| Old boundary | New boundary | Caller obligation |
|-
| Demand::new(program) | Demand::builder(program).build() | Production defaults retained |
| Demand::new_bounded(program, rows, policy) | builder(program).max_rows(rows).policy(policy).build() | Forced policy requires instrument |
| Demand::from_prepared(source) | Demand::prepared_builder(source).build() | Borrow source through build |
| Demand::from_prepared_bounded(source, rows, policy) | prepared_builder(source).max_rows(rows).policy(policy).build() | Row capacity is product configuration |
| ergodis_rules::Prepared | ergodis_rules::WeightedRulePlan | Migrate imports and annotations |
| check(program, certificate) | check(Source::Wire(program), certificate) | Explicit source regime |
| check_prepared(bytes, certificate) | check(Source::Prepared(bytes), certificate) | Bytes re-admitted by checker |
| source-specific bounded checks | check_bounded(Source, certificate, limit) | Direct-address budget remains available |
| evaluate(rir, source, externals, rows) | evaluate(rir, source, externals, EvaluateOptions) | Named cold configuration |

=check_recorded= remains the explicit verification-record issuer: it returns a
different result and has provenance work that an ordinary check need not pay.
=check_admitted= and its bounded form remain the documented in-process path;
they do not issue independently re-admitted provenance.

The rules =instrument= feature owns forced Policy variants, counted entry,
index lookup readout, index/membership plan reports and =reservations()=.
Auto, row bounds and workspace byte budgeting remain production capabilities.
The pages reservation counter also determines mapping offsets: hiding its
accessor must not remove its atomic increment or change reservation staggering.
No workspace shape change is intended.

The =policy= builder setter accepts Auto without the feature; only its forced
enum values require instrumentation. =Policy= retains one-byte representation
under both feature sets. The existing lookup-counter workspace allocation and
=Evaluation.lookups= field remain to avoid an unrelated layout/kernel change;
the production evaluation still selects its uncounted instantiation.

The private feature forwards to rules; tools opt in explicitly. The closure
harness retains default Auto evaluation/checking and refuses diagnostic flags
without =instrument=. The frontend's separate instrumentation is not moved.

* Policy records and trust

The RIR retains the actual body policy selected during lowering. Each layer
copies that value and its requested index policy into its report. Auto names
the selection policy, not a promise about every chosen representation.

These fields are operational accounting, not authenticated source provenance.
They do not extend the canonical RIR encoding, source identities, certificate
schemas or replay authority. Public replay consistency still does not establish
the original Rel source or authenticate omitted layer certificates.

** Review repairs before acceptance

- Primary review removed duplicated Auto policy logic introduced by conditional
  compilation, preserving one selection rule.
- Sol review found file/module feature gates that hid ordinary Auto sparse,
  large-universe, budget and workspace-reset tests. These now remain in the
  default suite; only representation reports and forced-policy cases are gated.
- Hiding the reservation accessor had weakened the default allocation test's
  mmap coverage. An isolated unit-test subprocess now checks the private counter
  around repeated real evaluation without races against parallel unit tests.
  Primary review caught its initial nesting error; the corrected child must
  report one passed test, so an empty test filter cannot pass the gate.
- The measurement driver retains its original =Demand::verify= calls. An
  unnecessary source clone/direct-checker rewrite was removed before retention
  so the measured boundary remains comparable.
- Policy reports describe requested operational configuration, not authenticated
  evidence. Source/certificate schemas and identities remain separate.
