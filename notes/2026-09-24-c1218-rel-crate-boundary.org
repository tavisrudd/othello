No source edits preceded retention.

The planned graph is =ergodis-rel-frontend= (std only) → =ergodis-rel-driver= (frontend + public contract/rules/verify); the private root and tools consume the small crates directly where needed. Neither extracted crate depends on the whole =ergodis= package, and public core never depends on a private crate. The frontend owns scanner, parser, diagnostic recovery, admission, RIR lowering and their fixed-capacity workspace. The driver owns typed readout, prepared-layer evaluation, transferable evidence and offline replay, weighted Rel routes and cold wire export. It does not duplicate the backend.

The extraction should change paths and imports only before measuring any optional instrumentation shape. External clients in this workspace should import the owning crate directly. A blanket re-export through =ergodis-private= would hide the dependency cut and is outside this design. The private root remains a library-only crate and task binaries stay under =tasks/=.

Inventory at the clean baseline: the frontend is =src/rel_frontend/{mod,lexer,parser,diagnostic,admit,corpus,lower}= plus the lowerer's three child modules, and its source has no external-crate imports. The driver is nine =src/rel_*.rs= modules: readout, stratified execution, transferable verification, wire export and five weighted-route modules. Its direct public dependencies are =ergodis-contract=, =ergodis-rules= and =ergodis-verify=; no driver source imports the whole =ergodis= crate. Outside those Rel modules, the private root still uses =ergodis-contract= in its Datalog certificate codec and =ergodis-verify= in two other modules; =ergodis-rules= has no non-Rel source use. Thus the latter dependency can leave the private root after the move, while the former two remain. The current root =instrument= feature forwards to =ergodis-rules= and will need a named driver/tools replacement rather than silently losing instrumentation.

The bare-rustc parity runner currently compiles =tests/rel_frontend_portability.rs= with =#[path = "../src/rel_frontend/mod.rs"]=. Retargeting that path to the new crate entry and including it in the runner's source-path manifest preserves the exact source-based byte check. It may change the manifest's source-file hash because paths move; this hash is not the canonical Rel output identity. The canonical native/WASM bytes and digest must remain equal to the baseline.

The root private =instrument= feature is used by no non-Rel source module. After the move it may remain only as a compatibility feature forwarding to the driver, while the tools' instrumentation feature should name the driver/rules explicitly. The frontend's =measurement= feature can expose benchmark-only scan/page-touch methods without forcing them into its ordinary library. The scalar parse variant remains a conformance method for native/WASM parity; its existence alone does not add per-token work to the default const-generic instantiation.

The first driver-only compile identified four frontend APIs that crossed the old module boundary invisibly: diagnostic refusals =refuse=/=refuse_span= and =Rir::source_limits=/=clone_filtered=. These will become explicit public methods/functions of the private std-only frontend crate with narrow contracts. No internal parser/admission pool needs broad exposure. This is a genuine new crate seam, not a reason to recreate =ergodis-private::rel_frontend= as a forwarding module.
