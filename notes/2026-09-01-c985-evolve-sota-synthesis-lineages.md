# C985 — Evolve SOTA, non-LLM synthesis lineages

status: complete (2026-09-01)

Scope: the non-LLM (and hybrid) program/predicate-synthesis and conjecturing
lineages whose problem shape matches Ergodis' `evolve` engine: discovering
*sound necessary conditions* (pruning theorems) over exact labelled corpora.
Companion to `notes/2026-08-30-c985-ergodis-evolve-sota-literature-audit.md`
(LLM evolutionary coders — AlphaEvolve, CodeEvolve, ShinkaEvolve/OpenEvolve,
test-time discovery, neural theorem proving), which this file does not re-cover.

Sections in progress below; see "Sources and read depth" at the end for what
was actually read.

## Ergodis shorthand used throughout

`evolve` = deterministic beam evolution of typed predicate plans; a small stack
VM over integer feature fields (field/const/`+ - *`/min/max/comparisons/and/or/
not/abs/select); ranked lexicographically by exact false positives (soundness),
covered positives, and syntax cost; with hashed outcome equivalence,
counterexample replay across campaigns, semantic niches, an exact
hindsight/theorem DAG, and a private zero-conjunction / constant-on-positive
proposer plus a pairwise-difference feature expander.

Two structural facts matter for every comparison below. First, Ergodis'
corpora are *exactly labelled and finite*, so a candidate's false-positive count
is a decided fact, not an estimate — there is no noise term and no statistical
generalisation gap over the corpus. Second, the object it wants is a **sound
necessary condition**: zero false positives is a hard constraint, and coverage
of positives is the objective. That is the shape of a *precondition inference*
or *dominance-breaking* problem far more than a regression problem.

## 1. Inductive logic programming with exact soundness constraints

### Canonical papers

- Cropper & Morel, *Learning programs by learning from failures*,
  arXiv:2005.02259 (v3), Machine Learning 110 (2021).
  The "generate, test, constrain" loop: hypotheses are generated by an answer
  set programming solver, tested against examples, and each failure is turned
  into a **constraint on the hypothesis space itself** rather than a fitness
  penalty. A hypothesis too general (covers a negative) yields a
  *specialisation* constraint pruning all its generalisations; too specific
  (misses a positive) yields a *generalisation* constraint pruning all its
  specialisations; a redundancy constraint prunes hypotheses subsuming a known
  failure.
- Cropper, Dumančić, Evans & Muggleton, *Inductive logic programming at 30*,
  arXiv:2102.10556, Machine Learning (2022). Survey organised around
  meta-level search, recursion, predicate invention, and new solver technology.
- Law, Russo & Broda, *The ILASP system for inductive learning of answer set
  programs*, arXiv:2005.00904; original *Inductive learning of answer set
  programs*, JELIA 2014, DOI 10.1007/978-3-319-11558-0_22. ILASP3/ILASP4 use
  conflict-driven ILP (CDILP): each iteration finds a *coverage conflict* and
  translates it into a constraint, i.e. the same anti-cycling idea reached
  independently.
- Aleph (Srinivasan) is the classical bottom-clause baseline: saturate one
  positive example into its most specific clause, then search generalisations
  of it. Still the reference point for "bound the space by an example".

### Repos

- `https://github.com/logic-and-learning-lab/Popper` — Python (SWI-Prolog +
  CP-SAT/NuWLS backends), ~315 stars, ~975 commits, actively maintained into
  2026. Supports noisy learning by minimum description length, recursion,
  predicate invention, typed and moded declarations.
- ILASP is distributed as binaries from `ilasp.com` / Imperial College, not as
  an open repo; the FastLAS and ILASP successors are the practical entry point.
- `https://github.com/friguzzi/aleph` (SWI-Prolog port) for the bottom-clause
  lineage.

### What Ergodis lacks and could import cheaply

1. **Failure-derived hypothesis-space constraints (Popper).** Ergodis' beam
   discards a failing plan and re-proposes near-duplicates of it forever. Popper
   turns each failure into an exact pruning rule over the *space*: if plan `P`
   admits a false positive, every logical weakening of `P` also does, so all of
   them can be refused at proposal time, not at evaluation time. Ergodis'
   predicate language has a usable weakening/strengthening order already —
   conjunction adds constraints, disjunction removes them, and comparison
   thresholds are monotone — so a half-day slice is: maintain two sets of
   "failed cores" (unsound-so-do-not-weaken, insufficiently-covering-so-do-not-
   strengthen) keyed by the same hash used for outcome equivalence, and reject a
   proposal whose normalised form is comparable to a stored core. This is
   strictly stronger than hashed outcome equivalence, which only rejects
   *identical* behaviour, never a provably-worse relative.
2. **Bottom-clause bounding (Aleph).** Take one uncovered positive, compute the
   set of ground feature relations that hold on it, and restrict the proposal
   grammar to literals drawn from that set. This is an hour-scale change to the
   proposer and directly targets the "which of the many feature fields should
   this plan even mention" question that the pairwise-difference expander
   currently answers by brute force.

### What Ergodis already does better

Popper and ILASP pay a solver call per hypothesis and are built for noisy,
relational, small-example regimes; their notion of "test" is set membership in
Prolog. Ergodis compiles candidates to a typed stack VM and evaluates them
exactly over large integer corpora with an allocation-free hot path, hashes
outcomes for equivalence, and replays counterexamples across campaigns. Nothing
in the ILP lineage has that throughput or that replay discipline. Ergodis'
theorem DAG also records *provenance of soundness*, which Popper does not.

## 2. Syntax-guided synthesis and CEGIS

### Canonical papers

- Alur, Bodík, Juniwal, Martin, Raghothaman, Seshia, Singh, Solar-Lezama,
  Torlak, Udupa, *Syntax-guided synthesis*, FMCAD 2013,
  DOI 10.1109/FMCAD.2013.6679385. Defines the SyGuS problem: a background
  theory, a semantic specification, and an explicit **grammar** bounding the
  candidate space. Ergodis' typed plan grammar is exactly a SyGuS grammar.
- Udupa, Raghavan, Deshmukh, Mador-Haim, Martin, Alur, *TRANSIT: specifying
  protocols with concolic snippets*, PLDI 2013, DOI 10.1145/2491956.2462174.
  Source of **observational-equivalence pruning** in enumerative synthesis:
  during bottom-up enumeration, two subexpressions agreeing on all inputs are
  interchangeable, so keep one. Ergodis' hashed outcome equivalence is the same
  idea applied at whole-plan level rather than at subexpression level.
- Alur, Radhakrishna, Udupa, *Scaling enumerative program synthesis via divide
  and conquer*, TACAS 2017, DOI 10.1007/978-3-662-54577-1_18 (EUSolver):
  synthesise point-wise-correct *terms*, then learn a decision-tree predicate
  that stitches them into a correct whole.
- Barke, Peleg, Polikarpova, *Just-in-time learning for bottom-up enumerative
  synthesis*, arXiv:2010.08663, OOPSLA 2020 (Probe): bootstrap a probabilistic
  grammar *during* the search from partial solutions — programs that satisfy
  some examples — and re-weight enumeration by it. No pre-training corpus.
- Lee, Hong, Ko et al., *Duet* (POPL 2021, DOI 10.1145/3434335) combines
  top-down propagation with bottom-up enumeration.

### Repos

- `https://github.com/cvc5/cvc5` — C++, very active, the reference SyGuS
  solver (`--sygus`); its enumerative and unification-based SyGuS engines
  implement observational equivalence and divide-and-conquer natively.
- `https://github.com/SynthesisLab/…` / `https://github.com/nadia-polikarpova`
  ecosystem for Probe; SyGuS-Comp benchmark sets at
  `https://github.com/SyGuS-Org/benchmarks`.

### What Ergodis lacks and could import cheaply

1. **Subexpression-level observational equivalence with a value bank
   (TRANSIT/bottom-up enumeration).** Ergodis hashes the *outcome* of a whole
   plan. Bottom-up synthesis instead keeps a bank of surviving subexpressions
   keyed by their full value vector on the corpus, and builds level `k+1` only
   from bank entries, so the entire space of behaviourally distinct
   subexpressions of a given size is explored once, ever. For a stack VM over
   integer fields this is a natural fit and is the single highest-leverage
   structural import in this report: it converts a beam that re-derives the
   same intermediate quantities into a deduplicated lattice. Half-day slice for
   a size-bounded version over a subsampled corpus (hash the value vector on a
   fixed sample, verify on the full corpus before admitting).
2. **Probe-style just-in-time grammar re-weighting.** Ergodis' proposer weights
   are static. Probe's rule — after each round, re-weight production
   probabilities by how often they appear in plans that covered *some*
   positives soundly — is an hour-scale change and gives directed exploration
   without any learned model or external dependency.

### What Ergodis already does better

SyGuS solvers verify against an SMT oracle and are therefore bounded by solver
capability and by specification writing; Ergodis verifies against an exact
finite corpus, which is decidable, fast, and needs no theory encoding. Ergodis
also carries a multi-objective ranking (soundness, coverage, cost) where SyGuS
is a satisfaction problem with no notion of "best partial theorem", and it keeps
counterexample replay across campaigns where a SyGuS run is one-shot.

## 3. Invariant inference from data

### Canonical papers

- Garg, Löding, Madhusudan, Neider, *ICE: a robust framework for learning
  invariants*, CAV 2014, DOI 10.1007/978-3-319-08867-9_5. The learner is fed
  positive points, negative points, **and implications** (`x ⇒ y` pairs) from a
  verifier; the teacher is a sound checker that returns a counterexample. The
  key property is *robustness*: the learner never has to guess, because every
  round is either a proof or a new exact datum.
- Garg, Neider, Madhusudan, Roth, *Learning invariants using decision trees and
  implication counterexamples*, POPL 2016, DOI 10.1145/2837614.2837664
  (ICE-DT). Decision-tree learning extended to implication samples, with a
  convergence guarantee.
- Padhi, Sharma, Millstein, *Data-driven precondition inference with learned
  features*, PLDI 2016, DOI 10.1145/2908080.2908099 (PIE), and *LoopInvGen*,
  arXiv:1707.02029. PIE starts with **no features at all** and synthesises new
  features on demand, precisely when the current feature set cannot separate a
  positive from a negative — a *conflict-driven feature expander*.
- Ernst et al., *Dynamically discovering likely program invariants* (Daikon),
  IEEE TSE 27(2), 2001, DOI 10.1109/32.908957: a fixed template library
  instantiated over observed traces, then falsified by data. Fast, unsound by
  design, used as a proposal generator.
- Fedyukovich, Kaufman, Bodík, *Sampling invariants from frequency
  distributions* (FreqHorn), FMCAD 2017: mine candidate invariants from the
  syntactic frequency distribution of the program text itself.

### Repos

- `https://github.com/SaswatPadhi/LoopInvGen` — OCaml, the SyGuS-Comp INV-track
  winner lineage; quiet but complete.
- `https://github.com/codespecs/daikon` — Java, actively maintained.
- `https://github.com/grigoryfedyukovich/aeval` (FreqHorn) — C++.
- HoIce, `https://github.com/hopv/hoice` — Rust, an ICE-based Horn solver; the
  closest thing to a Rust-native reference implementation of the ICE loop.

### What Ergodis lacks and could import cheaply

1. **Conflict-driven feature synthesis (PIE).** Ergodis' pairwise-difference
   expander is unconditional — it manufactures derived fields regardless of
   whether they are needed. PIE's rule is sharper and cheaper: find a
   *conflicting pair* (one positive and one false positive that the current
   feature vocabulary maps to identical values), and synthesise a new feature
   **specifically to separate that pair**. Since Ergodis already replays
   counterexamples, it already has the conflicting pair in hand; the slice is to
   route it into the expander instead of expanding blind. Half-day.
2. **Implication counterexamples / the "no guessing" discipline.** The ICE
   framing says the learner should never be asked to extrapolate: every
   hypothesis is either accepted by an exact check or refuted by a concrete
   datum that is added permanently. Ergodis' checker is already exact, but the
   *permanence* is partial — hard counterexamples should be promoted into a
   persistent minimal separating core that every future proposal is scored
   against first, before the full corpus. This is both a correctness discipline
   and a large constant-factor speedup (most bad plans die on ten rows).

### What Ergodis already does better

Daikon is explicitly unsound and template-bounded; LoopInvGen and FreqHorn are
tied to a program's syntax and to an SMT-backed teacher. Ergodis' corpus is the
ground truth, so its "teacher" is total and never times out — the ICE loop's
main practical failure mode (an SMT query that neither proves nor refutes)
simply does not exist here. Ergodis also ranks partial results; ICE-family tools
return one invariant or nothing.

## 4. Symbolic regression

### Canonical papers

- Cranmer, *Interpretable machine learning for science with PySR and
  SymbolicRegression.jl*, arXiv:2305.01582.
- Udrescu & Tegmark, *AI Feynman: a physics-inspired method for symbolic
  regression*, arXiv:1905.11481, Science Advances 6(16), 2020, DOI
  10.1126/sciadv.aay2631; and the Pareto-optimal successor *AI Feynman 2.0*,
  arXiv:2006.10782. The method that matters here is **recursive problem
  decomposition**: test the data for a structural property (separability,
  symmetry, dimensional constraints), and if it holds, split into two strictly
  smaller regression problems.
- La Cava et al., *Contemporary symbolic regression methods and their relative
  performance* (SRBench), arXiv:2107.14351, NeurIPS 2021 Datasets & Benchmarks.
  Findings that transfer: methods with an explicit accuracy-vs-complexity
  Pareto front dominate; simplicity bias is what makes a result *interpretable
  and reusable*, not just small; and the top performers are GP-based with
  strong deduplication, not the neural entrants.

### Repos

- `https://github.com/MilesCranmer/PySR` — Python front end over Julia
  (`SymbolicRegression.jl`), ~3.7k stars, ~2900 commits, active in 2026,
  Apache 2.0. Ships: Pareto front model selection by complexity, multi-
  population "island" evolution, expression deduplication/hash-consing, and
  automatic simplification of discovered expressions.
- `https://github.com/cavalab/srbench` — the living benchmark.
- `https://github.com/SJ001/AI-Feynman` — Python, reference implementation,
  low activity.

### What Ergodis lacks and could import cheaply

1. **Explicit Pareto archive over (coverage, syntax cost) at fixed zero false
   positives.** Ergodis ranks lexicographically, which collapses the trade-off
   into a single winner per round and silently discards a cheap
   80%-coverage theorem in favour of an expensive 82% one. A sound necessary
   condition is *more* valuable when it is cheap to evaluate inside a solver hot
   loop, so cost is a first-class objective, not a tiebreak. Keeping the
   non-dominated front is an hour-scale change and immediately gives the solver
   a menu of pruning theorems to install at different price points.
2. **AI Feynman-style structural decomposition tests.** Before searching, probe
   the corpus for separability — does the positive set factor as a conjunction
   over disjoint field groups? — and if so, search the groups independently.
   For Hadamard/Goethals–Seidel blocks with CRT multiplier orbits the field
   groups are already meaningful (per-orbit aggregates), so the test is cheap
   and the search-space reduction is multiplicative.

### What Ergodis already does better

Symbolic regression fits real-valued data with a tolerance and has no soundness
notion at all; a PySR expression is never a theorem. Ergodis' integer/exact
semantics, typed genome, and zero-false-positive hard constraint are the whole
point and must not be traded for a fitting objective. Import PySR's *search
bookkeeping* (Pareto front, islands, hash-consing) and none of its *objective*.

## 5. Conjecture generation in combinatorics and graph theory

### Canonical papers and systems

- Fajtlowicz, *On conjectures of Graffiti* (Discrete Mathematics 72, 1988,
  DOI 10.1016/0012-365X(88)90189-6, and the Graffiti series). The origin of
  data-driven conjecturing: compute invariants on a stock of graphs, propose
  inequalities that hold on all of them, and filter aggressively. The **Dalmatian
  heuristic** is the filter that matters: a new conjecture is retained only if
  it is *not implied* by the conjunction of the conjectures already retained
  **and** it is sharp on at least one object in the stock. That is a
  significance test, not an accuracy test.
- Davila, *Automated conjecturing in mathematics with TxGraffiti*,
  arXiv:2409.19379 (v2, May 2026), accepted to Annals of Mathematics and
  Artificial Intelligence. Modernises Graffiti over a versioned snapshot table
  of objects with precomputed integer invariants and Boolean predicates;
  proposes linear and ratio bounds *restricted to classes* picked out by the
  Boolean predicates; keeps the Dalmatian filter. Several TxGraffiti outputs
  became published theorems (e.g. arXiv:2104.01092 on independence, domination
  and matchings).
- Davila, *The Optimist: towards fully automated graph theory research*,
  arXiv:2411.09158 (Nov 2024). Conjecture generation via mixed-integer
  programming plus heuristics, with memory-based iterative refinement, and an
  explicitly named adversary ("the Pessimist", human or machine) that supplies
  counterexamples — a conjecturer/refuter duel.
- Wagner, *Constructions in combinatorics via neural networks*,
  arXiv:2104.14516. The deep cross-entropy method searching the space of
  *constructions* (not statements) refuted conjectures on permanents of
  pattern-avoiding matrices and on adjacency/distance eigenvalues. Relevant
  because the objects are exactly verified: a construction either is a
  counterexample or is not.
- Charton, Ellenberg, Wagner, Williamson, *PatternBoost: constructions in
  mathematics with a little help from AI*, arXiv:2411.00566. Alternates a
  **local phase** (classical search producing many good constructions) with a
  **global phase** (a transformer trained on the best of them, then sampled to
  seed the next local phase). Produced a counterexample to a 30-year-old
  conjecture. The interesting part for Ergodis is not the transformer but the
  alternation schedule: cheap exact search generates the training signal, and
  the learned component only reseeds.
- Raayoni et al., *The Ramanujan Machine: automatically generated conjectures
  on fundamental constants*, arXiv:1907.00205, Nature 590, 67-73 (2021),
  DOI 10.1038/s41586-021-03229-4. Meet-in-the-middle and gradient-descent
  searches over continued-fraction forms, matched numerically. Explicitly
  conjectures without proof — the *opposite* of Ergodis' contract, and a useful
  contrast: numerical matching cannot be a soundness certificate.

### Repos

- `https://github.com/RandyRDavila/Linear_TxGraffiti` (and `TxGraffiti` /
  `graffitiai` packages) — Python, small, actively developed by the author.
- `https://github.com/zawagner22/cross-entropy-for-combinatorics` — Python,
  Wagner's reference code; widely forked.
- `https://github.com/zawagner22/transformers_math_experiments` — PatternBoost.
- `https://github.com/RamanujanMachine/RamanujanMachine` — Python.

### What Ergodis lacks and could import cheaply

1. **The Dalmatian filter.** Ergodis has no notion of a candidate theorem being
   *redundant given the theorems already banked*. A plan whose covered-positive
   set is a subset of the union of already-accepted plans adds nothing to the
   pruning power of the theorem library, however good its individual score is.
   Dalmatian says: accept only if it covers at least one positive no accepted
   theorem covers, and it is *tight* somewhere (there is an object where the
   condition is met with equality / is the binding constraint). Ergodis already
   stores per-plan outcome bitsets, so this is an hour-scale change on the
   acceptance path and it directly attacks the observed failure mode of banking
   many near-duplicate theorems.
2. **Class-restricted conjectures (TxGraffiti).** Propose `class predicate ⇒
   bound` rather than a single global bound. Ergodis' language can express this
   (`select`/implication via disjunction), but nothing in the proposer *aims*
   at it. Seeding proposals with a Boolean field as the antecedent and searching
   only the consequent is a small proposer change and turns "no sound global
   condition exists" into "a sound condition exists on 60% of the corpus",
   which is still a usable pruning theorem.
3. **PatternBoost's alternation as a schedule, without the transformer.**
   Local phase = the existing beam; global phase = refit the proposer
   distribution on the best constructions found so far (this composes with the
   Probe re-weighting in section 2). Sub-hour once the Probe change exists.

### What Ergodis already does better

Graffiti/TxGraffiti conjectures are *empirical over a stock* — true on the
snapshot table, unproven in general — and the Optimist needs an external
Pessimist to refute. Ergodis' corpora are exhaustive over a bounded region, so a
zero-false-positive plan is a decided fact on that region, not a conjecture,
and refutation is internal. Ergodis also has a typed genome with arithmetic
structure, where TxGraffiti's hypothesis language is essentially linear/ratio
inequalities between named invariants.

## 6. Quality-diversity and multi-objective genetic programming

### Canonical papers

- Mouret & Clune, *Illuminating search spaces by mapping elites* (MAP-Elites),
  arXiv:1504.04909. Keep the best solution *per cell* of a user-chosen
  behaviour-descriptor space rather than one global best; the archive both
  explains the space and, by preserving stepping stones, finds better global
  optima than single-objective search.
- Vassiliades, Chatzilygeroudis, Mouret, *Using centroidal Voronoi tessellations
  to scale up the multi-dimensional archive of phenotypic elites algorithm*
  (CVT-MAP-Elites), arXiv:1610.05729, IEEE TEVC 22(4), 2018,
  DOI 10.1109/TEVC.2017.2735550. Replaces the grid by a fixed number of
  Voronoi centroids, so archive size is chosen independently of descriptor
  dimension — the fix for high-dimensional behaviour descriptors.
- Lehman & Stanley, *Abandoning objectives: evolution through the search for
  novelty alone*, Evolutionary Computation 19(2), 2011,
  DOI 10.1162/EVCO_a_00025.
- Deb, Pratap, Agarwal, Meyarivan, *A fast and elitist multiobjective genetic
  algorithm: NSGA-II*, IEEE TEVC 6(2), 2002, DOI 10.1109/4235.996017.
  Non-dominated sorting plus crowding distance — the standard way to hold an
  accuracy-versus-complexity front in genetic programming.

### Repos

- `https://github.com/icaros-usc/pyribs` — Python, ~262 stars, active in 2026,
  MIT. Modular archives/emitters/schedulers; implements CMA-ME, CMA-MEGA,
  CMA-MAE and scalable variants; the cleanest reference for archive mechanics.
- `https://github.com/adaptive-intelligent-robotics/QDax` — Python/JAX,
  hardware-accelerated MAP-Elites variants.
- `https://github.com/MilesCranmer/SymbolicRegression.jl` — Julia; its island
  model plus complexity-indexed Pareto front is a working QD-flavoured GP
  archive for expressions, and the closest analogue to what Ergodis wants.

### What Ergodis lacks and could import cheaply

1. **A principled descriptor space for the semantic niches, with CVT sizing.**
   Ergodis has semantic niches already, but they are defined ad hoc. The
   MAP-Elites framing says: choose descriptor axes that are *cheap, meaningful,
   and orthogonal to the objective* — for pruning-theorem discovery the obvious
   ones are (number of feature fields referenced, VM instruction count /
   evaluation cost, fraction of corpus on which the predicate is *active*
   rather than vacuously true). Keeping one elite per cell over those axes is a
   direct upgrade of the existing niche code, and CVT sizing removes the
   curse-of-dimensionality objection if a fourth axis is wanted later.
2. **NSGA-II non-dominated sorting on the front kept in section 4.** Once
   coverage and cost are both objectives, crowding-distance selection is the
   standard, cheap way to keep the front spread instead of clustered. Sub-hour.

### What Ergodis already does better

Quality-diversity is a black-box stochastic framework; Ergodis is deterministic
and its "fitness" is an exact decided quantity, so its archive is reproducible
and its elites are certified. Determinism is a real asset for a system that
must produce auditable theorems and must not regress: keep it, and implement
any archive as a deterministic tie-broken structure.

## Direct competitors and precedents

The question "does anything already do sound pruning-theorem synthesis for
exact combinatorial search, head-on?" has one clear yes, from constraint
programming rather than from machine learning:

- **Automatic dominance breaking (Lee & Zhong).** *Automatic dominance breaking
  for a class of constraint optimization problems*, IJCAI 2020,
  `https://www.ijcai.org/proceedings/2020/0166.pdf`; *Automatic generation of
  dominance breaking nogoods for a class of constraint optimization problems*,
  Artificial Intelligence 322 (2023), DOI 10.1016/j.artint.2023.103952;
  *Exploiting functional constraints in automatic dominance breaking for
  constraint optimization*, CP 2022 / JAIR (DOI 10.4230/LIPIcs.CP.2022.31,
  10.1613/jair.1.14714). This is the same product Ergodis is after — **sound,
  automatically generated constraints that prune an exact search without
  losing solutions** — reached by a different route: the target problem class
  is restricted (efficiently checkable objectives and constraints, aggregation
  functions with monotonicity/commutativity/associativity), and nogood
  generation is posed as an *auxiliary constraint satisfaction problem* whose
  every solution is a provably sound dominance nogood. Soundness is by
  construction, not by corpus evaluation, and nogood strength is controlled by
  bounding the number of variables involved. Treat this as precedent and as the
  method to cite and compare against, not as a threat: it requires the problem
  to be expressible in that restricted COP form, whereas Ergodis works from
  labelled corpora of already-computed objects and can find conditions whose
  soundness argument nobody has written down.
- **Certified symmetry and dominance breaking** (Bogaerts, Gocht, McCreesh,
  Nordström), arXiv:2203.12275, JAIR 77 (2023); and *The strength of the
  dominance rule*, arXiv:2406.13657. Pseudo-Boolean/cutting-planes proof
  logging (VeriPB) makes an applied dominance or symmetry-breaking step
  machine-checkable. This is the natural *output format* for an Ergodis
  pruning theorem if it is ever to be believed outside this repository: the
  theorem plus a proof-log justification, checked independently.
- **Symmetry breaking for inductive logic programming**, arXiv:2508.06263
  (2025) — the ILP side rediscovering the same need; worth a read before
  designing Ergodis' own symmetry handling on CRT multiplier orbits.

No system found does this *from labelled corpora over an evolving typed
predicate language with exact replay*; that combination remains Ergodis'
position. This report makes no novelty claim — the searched channels are listed
below and do not include MathSciNet, zbMATH, or forward-citation closure.

## Where to take evolve

Ranked by expected value for sound-necessary-condition discovery per unit of
implementation effort. "Size" is a working estimate for one focused session.

1. **Failure-derived generalisation/specialisation constraints** (ILP / Popper).
   Store each failure as a *core* in the plan-normal-form hash and refuse any
   proposal comparable to it under the weakening order. Expected win: the
   largest single reduction in wasted evaluations; it converts the beam from
   "forget and re-propose" to monotone space contraction, which is also the
   anti-cycling property the current engine lacks. Size: half day.
2. **Subexpression value bank with observational equivalence** (SyGuS /
   TRANSIT). Bottom-up construction from a bank keyed by value vectors, with
   sample-hash then full-corpus verification. Expected win: multiplicative —
   every behaviourally distinct subexpression is built once ever, which is
   exactly the regime where a stack VM over integer fields pays off. Size: half
   day for a size-bounded version.
3. **Dalmatian acceptance filter** (Graffiti / TxGraffiti). Accept a theorem
   only if it covers a positive no banked theorem covers *and* is tight
   somewhere. Expected win: the theorem library stops filling with
   near-duplicates, and library size becomes a meaningful measure of progress.
   Size: about an hour on the acceptance path.
4. **Pareto front over (coverage, evaluation cost) at zero false positives**
   (symbolic regression / NSGA-II). Replace the lexicographic single winner
   with a non-dominated front plus crowding-distance spread. Expected win: the
   solver gets a menu of pruning theorems at different price points, and cheap
   high-coverage conditions stop being discarded. Size: about an hour, plus an
   hour for crowding distance.
5. **Conflict-driven feature synthesis** (PIE / LoopInvGen). Trigger the
   pairwise-difference expander only on an actual conflicting
   positive/false-positive pair, and aim it at separating that pair. Expected
   win: kills the blind expansion cost while raising the hit rate; composes
   directly with the existing counterexample replay. Size: half day.
6. **Persistent minimal separating core from replayed counterexamples** (ICE).
   Promote the hardest counterexamples into a small row set that every proposal
   is scored on first. Expected win: a large constant-factor speedup — most
   unsound plans die on a handful of rows — plus a cross-campaign regression
   guard. Size: half day.
7. **Class-restricted proposals** (TxGraffiti). Search `antecedent ⇒
   consequent` with a Boolean field as antecedent. Expected win: recovers
   usable pruning theorems on problems where no sound global condition exists.
   Size: a few hours in the proposer.
8. **Probe-style just-in-time proposer re-weighting, with a PatternBoost
   alternation schedule.** Re-weight production probabilities each round by
   their frequency in sound partial-coverage plans; alternate exploit rounds
   with re-seeding rounds. Expected win: directed exploration with no learned
   model and no external dependency; preserves determinism if the re-weighting
   is a pure function of the round's results. Size: about an hour, plus an hour
   for the schedule.
9. **MAP-Elites descriptor axes for the semantic niches** (fields referenced,
   VM cost, activity fraction), with CVT sizing if a fourth axis is added.
   Expected win: niches become interpretable and the archive becomes a map of
   what kinds of theorem exist, which is directly reportable. Size: a few hours
   on the existing niche code.
10. **Proof-log output format for banked theorems** (certified dominance
    breaking / VeriPB). Emit each accepted pruning theorem with a
    machine-checkable justification of its application in the solver. Expected
    win: makes an Ergodis-derived pruning step citable and independently
    checkable, which is the difference between an internal speedup and a
    paper-facing result. Size: larger than the rest — a design task, not a
    session — but the single highest-value item for external credibility.
11. **Structural separability probe before search** (AI Feynman). Test whether
    the positive set factors over disjoint field groups (per-orbit aggregates
    for the CRT multiplier case) and search groups independently if so.
    Expected win: multiplicative search-space reduction when the test fires,
    zero cost when it does not. Size: a few hours.

Items 1-4 are the recommended first batch: they are independent of each other,
each is at most half a day, and together they change the beam from a
memoryless ranked search into a space-contracting archive search without
touching the exact evaluation semantics.
