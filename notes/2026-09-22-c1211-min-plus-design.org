#+DATE: 2026-09-22
#+STARTUP: overview

* Status and decision

DECIDED 2026-09-23. Tavis delegated the architecture choice and required full
certification on demand with negligible off-path cost, no evaluator slowdown
when checking is requested, and no growth of the normal result. This memo
changes no Rust source or schema. It pins core =8aec9aba= and private
=cddd241e=. Native and WASM performance figures below are cost models, not
measurements.

Decision: a *separate weighted relaxation kernel* in =ergodis-rules=,
sharing cold admission, join-shape and index-shape machinery with =Demand=
where source contracts genuinely coincide. Give it its own cost columns,
update queue and worker workspace. The ordinary weighted result carries only
keys and minimum costs. An optional *detached value certificate* binds the
canonical prepared source and result; an independent checker reconstructs
finite support and proves global closure. It retains no producer witness or
rank in the evaluator and emits no proof rows in the ordinary result. Keep
Boolean =Demand= and its current certificate bytes and hot row layout
unchanged. C1194 implements this choice.

* Proposed admitted fragment and mathematical meaning

For each weighted relation, designate one integer *cost column*. The key is
the remaining tuple. A structural Boolean relation contributes zero cost when
its tuple is present. A cost-bearing input fact supplies one finite cost; two
facts with the same relation/key combine by =min=. A rule's admitted cost
expression is exactly the sum of every cost-bearing body factor once, plus
nonnegative integer literals and nonnegative typed integer *key fields* bound
by its body. An ordinary structural body factor contributes zero as a
relation, while one of its integer fields may supply an explicit addend.
The resulting per-match offset is independent of the *current costs* of
recursive rows. The head uses =min= to combine candidate costs for one key. The
lowering must normalize source =+= expressions to this form and reject a
missing, repeated or extra cost variable. It must also reject subtraction,
multiplication, a negative cost, a non-integer cost, and cost-dependent
negation or filtering comparison inside the recursive weighted layer. A
single defining equality for the head cost is cost construction, not a
filter; C1194's implementation plan pins its Rel source pattern. General
=count/max/sum= over a weighted recursive relation remains outside this
fragment; a completed earlier layer may be materialized as immutable input.
Every structural relation read by a weighted strongly connected component
is an input or a certified earlier-layer closure, frozen at that layer's
entry. Same-layer structural recursion needs a separate mixed-carrier proof
and is rejected in this first fragment.

For relation/key coordinate =x=, let ~B(x)~ be the minimum input cost or
=INF=. For a rule match =m= with body coordinates =p_1,...,p_k= and the
nonnegative offset =c_m= computed from its bound integer key fields and
literals, define ~W(m) = c_m + sum_i V(p_i)~ using checked nonnegative addition.
The intended valuation is the *least fixed point in the information order*
(reverse numeric cost order), equivalently the minimum over finite
derivation trees:

  ~V(x) = min(B(x), {W(m) : m heads x})~.

This is finite-domain relational min-plus. In the initial fragment every
accepted cost is in =0..u32::MAX=, excluding the sentinel itself. Rel's
=i64= literal is converted only after checking =0 <= value < u32::MAX=.
Arithmetic uses a wider temporary or checked addition. A result at or above
the sentinel causes an explicit cost-range refusal with the source term/rule
span; no successful execution or certificate silently treats that path as
absent. This is deliberately conservative: a dominated overflowing path can
refuse an otherwise representable answer. C1194 must report that refusal as
a diagnostic, including the limit and offending expression, and test it.
Both producer and checker must compute the checked sum of every actual rule
match before comparing it with the current head minimum; skipping a dominated
match could otherwise make an unchecked run succeed while checking refuses.
It may later prove a less conservative rule separately; no unbounded-integer
optimality is claimed from saturating =BoundedMinPlus= alone.

The fragment is per layer. A weighted strongly connected component is
monotone because all costs and offsets are nonnegative and alternatives take
=min=. Boolean strata can supply frozen structural facts. A later stratum
may inspect a certified weighted closure. Carrier choice is part of the
layer's admitted source and cannot be inferred just from seeing a =min=
boundary aggregate.

* Alternatives and decision

| Option | Data flow and updates | Setup/memory | Main risk |
|-
| Extend =Demand= and =DemandWorkspace= | Add a cost to each Boolean row; change duplicate handling and delta semantics in its existing loops | Reuses every plan/index and row reservation, at least one 4-byte cost column plus queues per row | Changes the measured Boolean kernel, row layout and =old/delta= assumptions; source and certificate branches invade its hot path |
| Separate weighted kernel, shared cold shapes (chosen) | Prepare relation/atom/join/index shapes once; weighted execution owns tuple-to-row membership, cost columns, improvement queues and specialized join loops | Small cold shape extraction; second workspace and compiled hot loop; row costs/queue state separately budgeted | Some intentionally distinct hot-loop code and checker work; cold sharing must be measured for Boolean codegen |
| Wholly independent weighted kernel | Copy planner, index builder and admission conventions as well as execution | Simplest isolation at first edit; duplicated cold work and tests | Planner policy, identity and portability behavior drift over time |

The middle option is a *second kernel*, not a second engine or host. Its common
pieces are finite source admission, relation/key definitions, join order,
addressing-kind choice, packed-key helpers and =Pages= backing. Boolean and
weighted execution have different state transitions and remain specialized.
If extracting cold helpers changes Boolean ThinLTO output, C1194 measures and
either repairs that shape or keeps a small bounded cold duplication until it
can share safely. No generic callback, trait object or carrier switch enters
either tuple loop.

* Recommended preparation, workspace and updates

1. Lower Rel's weighted layer to a *weighted prepared source*, separate from
   the current Boolean =PreparedSource=: relations with key arity and cost
   position, canonical cost-bearing input rows and frozen structural input
   rows, a typed value table for every
   key-domain ID (integer entries carry the signed payload), rules with
   key atoms and a bounded list of offset addends (literal or body atom/typed
   integer column), and the declared carrier. Validate that every addend is
   bound and nonnegative when evaluated; include the value table and addend
   descriptors in the source identity. The checker decodes every typed value
   strictly: malformed integer payloads are refused, never treated as zero.
   Without the value table a checker
   cannot independently recompute =edge(...,w)= from a dictionary ID. The cost column
   is not a tuple-key digit. Normalize duplicate input keys to their minimum
   cost before calculating the source identity. Keep a domain-separated
   canonical encoding so a third party can re-admit the exact source.
2. Build the same kind of immutable relation/index shapes =Demand= uses where
   they apply. A weighted step chooses one body relation as its changed input
   and joins it against all currently present coordinates. It must not reuse
   Boolean =old= row cutoffs: an existing coordinate can improve without a
   new row. Run-constant body width and addressing kind dispatch once outside
   each weighted join loop. A one-time seed pass evaluates rules whose bodies
   use only frozen structural relations; they have no weighted input event
   to trigger them.
3. The weighted workspace holds one row per relation/key, a parallel =u32=
   best-cost column, and two bounded queues of improved row IDs. Membership
   and join indexes map tuple keys to *stable row IDs*. Inserting a new key
   adds one row and indexes it; lowering an existing cost updates that row
   and enqueues it without reinserting it into an index. A per-row epoch/flag
   coalesces repeated improvements within a wave. The next wave scans every
   changed row in every body position. A row changed while its current wave
   is scanned remains scheduled for a later wave. No queue grows at runtime.
4. The producer stops only when the improvement queue is empty. It retains
   separate counts for distinct rows, strict relaxations, join probes,
   candidates and waves. A row bound limits *keys*, while a work/event budget
   limits repeated improvements; exhaustion returns a refusal, never an
   incomplete certificate. A nonnegative finite-domain program has only
   finitely many strictly decreasing =u32= coordinate values, so fair
   relaxation terminates in principle. The Boolean rule =rounds <= rows+1=
   does not apply: cost may improve many times with no new row. The grounded
   scalar convergence bound is not an implementation bound for this lazy
   relation store without its own finite-coordinate argument. If the queue
   empties while some final rule match could lower its head, choose that
   match's last-improved weighted premise: its eventual scan saw all other
   final premise costs and would have enqueued the head. Structural-only
   rules were handled by the seed pass. Thus an empty queue implies local
   closure, provided every improvement is eventually scanned.
5. Deletions, increases of a fact cost and changed rules invalidate the
   source-bound workspace and trigger re-admission/recomputation in C1194.
   A lower input cost admits a decrease-only incremental route in principle,
   but it is not part of the first contract. Existing certificates never
   transfer to a new source identity by themselves.

Cost model before implementation: for =R= retained distinct rows and =A=
strict improvements, tuple/index storage scales with =R=, while the work of
join propagation scales with the candidate matches visited over =A= events.
The additional hot storage is at least one 4-byte cost, approximately two
4-byte queue slots and one 4-byte queue flag/epoch per potential row: about
16 bytes per row of capacity before indexes, page staggering and cold
checking. A capacity of one million rows therefore reserves
roughly 16 MB for these columns, not a measured RSS prediction. On native
Unix =Pages= can commit only touched rows; on WASM/other non-Unix its fallback
commits the reservation eagerly. Preflight total reserved bytes under the
product budget and offer explicit smaller row bounds on memory-limited hosts.

* Detached certification and independent check

The selected certificate is the canonical *weighted result claim*: for every
finite weighted relation/key, exactly one =u32= minimum cost, sorted in a
specified order, with no infinity rows. A small separate versioned envelope
binds the domain-separated canonical prepared-source digest and canonical
result digest. The result already contains every value a checker needs; the
envelope duplicates no tuple, cost or proof row. If the caller only needs
values, neither envelope nor checker is constructed. A verified result is
the pair of admitted source and result *after* the independent checker
accepts. The binding envelope by itself is a claim, not evidence of
correctness or a trusted attestation.

The evaluator's API exposes normal =evaluate(source, workspace) -> result=.
The opt-in API runs that *identical* evaluator first, freezes its canonical
result, then invokes a separate checker over serialized source and result.
There is no =certify= flag, witness/rank field, certificate branch, hash, or
serialization step in the weighted join/relaxation loop. Boolean =Demand=
keeps its own path. To avoid ThinLTO changing the evaluator merely because
the checker is linked, measure the evaluator's loop and result bytes with
and without the opt-in route; if code shape changes, isolate the checker in
the existing verify crate or a separate linked entry point and retain the
matched evaluator binary. The *total* checked operation necessarily costs
more than evaluation alone. Report evaluator and checker instruction/time/RSS
separately; do not describe the full checked operation as zero cost.

The independent checker re-admits the weighted prepared bytes, decodes every
typed value strictly, recomputes source identity, checks the envelope's
source/result digests, and validates canonical result order, unique keys,
arity, domains, finite cost range, declared relation coverage, and checked
arithmetic. It builds its own bounded indexes. Its *support pass* starts by
marking listed rows whose claimed cost equals an admitted input fact. It
repeatedly joins source rules over already marked weighted rows and frozen
structural rows, marking a listed head only when its claimed cost equals the
checked candidate sum. A structural-only rule joins in the initial seed
pass. Each mark corresponds to a finite source-rooted proof tree; all finite
claimed rows must eventually be marked. Unsupported zero-cost cycles remain
unmarked. The checker may use an internal rank or work queue, but neither is
serialized or supplied by the producer. To prevent a producer bug from being
masked by code reuse, support and closure use checker-owned iteration and
indexing, not the producer's plan or join cursor.

Its separate *closure pass* checks every weighted source fact has a listed
cost no greater than its cost and joins every source rule over *all* listed
finite weighted rows and frozen structural rows; each match's weighted head
must exist at a cost no greater than the candidate. Resource exhaustion is a
refusal, never acceptance. Only after both passes succeed may the checker
issue a verification record binding the source digest, result digest,
checker identity and check outcome. A recipient must trust or rerun that
checker; the record is not a cryptographic proof of execution. A checker
called on an in-process admitted object is an explicitly weaker fast path.

Correctness argument on paper: every marked finite row is rooted at an
input fact or exact rule match on earlier marked rows, so it has a finite
proof tree of exactly its claimed cost. The true minimum is at most the
claim (*support soundness*). Closure says every fact and rule candidate is
at least the claimed head cost; induction over finite proof trees says every
claim is at most every derivable cost (*completeness*). Together these give
equality, and closure forbids finite derivations for absent coordinates.
For a minimum-cost proof tree, replacing any premise by a cheaper final proof
could only lower its head; closure would then be contradicted. A minimum
depth tree among equal-cost alternatives breaks zero-cost cycles, so the
marking pass can discover all valid claimed rows. The Boolean version is:
supported rows lie in the least model, while a closed set contains it. This
is the relational support-plus-closure proof, not a grounded-certificate
claim. C1217 may formalize it; no Lean work or formal-coverage claim is made
here.

If measured checker time for repeated third-party verification is too high,
a later *optional* detached rank sidecar may give each result row a compact
support rank. It must be independently checked and must not change the
evaluator or normal result format. It is not a prerequisite for full
certification in C1194 and cannot substitute for the closure pass.

* Worked recursive examples

The following is semantic notation, not a claim that today's Rel parser
accepts this exact syntax.

** Shortest paths, one key improved twice

Input: ~dist(A)=0~; structural rows =edge(A,B,2)=, =edge(B,C,3)=,
=edge(A,C,9)=, where the third column is a typed nonnegative integer.
Rule: =dist(v) <- dist(u) + w, edge(u,v,w)=, with min alternatives.

| Wave | dist(A) | dist(B) | dist(C) |
|-
| input | 0 | INF | INF |
| 1 | 0 | 2 | 9 |
| 2 | 0 | 2 | 5 |
| fixed | 0 | 2 | 5 |

=C= retains one row: its cost changes =9 -> 5=. A valid final witness is
~dist(A)=0 -> dist(B)=2 -> dist(C)=5~, using both edge rows; the direct
cost-9 proof remains a nonminimal alternative checked by closure.

** Minimum component label through zero-cost edges

Input vertex labels: ~label(1)=1~, ~label(2)=2~, ~label(3)=3~,
~label(5)=5~. Undirected structural edges join =1-2= and =2-3= at cost zero.
Rule: =label(v) <- label(u) + link(u,v)=; the link contributes zero.

| Wave | label(1) | label(2) | label(3) | label(5) |
|-
| input | 1 | 2 | 3 | 5 |
| 1 | 1 | 1 | 2 | 5 |
| 2 | 1 | 1 | 1 | 5 |
| fixed | 1 | 1 | 1 | 5 |

The zero-cost cycle does not justify a label by itself; checker support starts
from an input label. This example tests min aggregation independently of
positive path weights.

* Shortcuts rejected by distinguishing counterexamples

| Shortcut | Counterexample and wrong result |
|-
| Keep cost as part of the tuple key / set union | In the shortest-path example, =(C,9)= and =(C,5)= coexist; the relation no longer has one minimum per key. |
| First derivation wins / append-only Boolean =emit= | The direct =A -> C= path inserts 9 before the route through =B= gives 5; the wrong result is 9. |
| Stop after =rows+1= waves | One row can successively improve =9 -> 7 -> 5= without adding a key; a row-count guard can stop before 5. |
| Support witnesses without closure | ~dist(C)=9~ has a real direct-edge proof but omits the available cost-5 route. |
| Closure inequalities without source-rooted support | With no facts and rules =p <- q + 0=, =q <- p + 0=, the false claim ~p=q=0~ is locally closed but has no finite proof. |
| Boolean support reused as a weighted certificate | An edge of cost 4 supports the *presence* of =dist(B)=, but a claimed cost 0 is false. |
| Grounded min-plus certificate reused by schema | A three-atom relational body is admitted by Demand but has no grounded two-factor rule or matching source identity. |
| Saturation silently treated as absence | A source path costing =u32::MAX-1= followed by a weight-1 edge reaches its endpoint mathematically, while saturation labels it =INF=. |
| Decrease-only propagation after an increase/deletion | Change the only =A -> B= edge from cost 2 to 8: retaining ~dist(B)=2~ is stale; restart or dependency invalidation is required. |

* C1194 implementation and verification gate

1. Record the approved choice in C1194's card. Define the weighted prepared
   contract, domain-separated encoding and checked re-admission before the
   producer. C1194 must give diagnostics for invalid =i64= costs, malformed
   =+= cost normal forms and representational overflow. Key-producing
   arithmetic beyond this cost fragment needs its own bounded-domain
   admission design and is not claimed by this memo. No existing Boolean schema,
   source identity or certificate encoding changes.
2. Implement the weighted kernel and source-bound workspace under the common
   core; preserve Boolean code shape, zero allocations in repeated weighted
   evaluation, no runtime-length libc calls or per-tuple carrier dispatch.
   Pre-size row stores, improvement queues and indexes. Profile both kernels
   and measure any shared cold-plan extraction against retained binaries.
   Since the weighted kernel has no retained predecessor, its first
   acceptance also records an instruction and nanosecond budget per row,
   candidate and strict relaxation on named workloads, plus a retained
   weighted binary for its next change.
3. Implement the detached value-claim envelope and independent support and
   closure checker with bounded memory, malformed/mutated result and envelope
   cases, zero-cost unsupported cycles, missing cheaper paths and
   source/cost/offset binding. The normal evaluator returns the same bytes
   and uses the same hot code whether checking follows or not. Do not issue a
   verification record from the producer's admitted fast path. Measure the
   checker separately and test a certificate-free call path with no witness,
   rank, digest or certificate allocations in the evaluator.
4. Extend the Rel route and its independently written naive reference over
   the admitted AST, not over RIR or the weighted plan. Run SSSP and component
   labels plus seeded differential cases for duplicate facts, multiple cost
   improvements, zero/positive cycles, three/four-body joins, constants,
   overflow and layer interactions. On the overlap with the grounded language
   (small finite domain, up to two factors), compare valuations with the
   existing grounded min-plus oracle; neither certificate is interchangeable.
5. Use the current pinned native/wasm32 build and exactness gates. For every
   hot-loop or hot-record edit use =PERFORMANCE.md='s retained-control,
   interleaved instruction/cycle/branch/cache, profile, allocation, parity,
   single/parallel where applicable and RSS requirements. The C1194 lower
   stage needs its own matched parse/admit/lower A/B. Retain clean current
   core/private controls *before* C1194 edits: the older
   =ergodis-tools-e0e7331= named on C1194's card is historical context, not
   a matched immediate control after the subsequent API and driver changes.
   Include both opt-in and ordinary output byte comparisons; distinguish
   evaluator latency from post-evaluation checking latency. Add a coverage table
   per arithmetic form: parsed, admitted, lowered, executed, certified.

Unresolved risks owned by C1194's implementation and measurement: the
weighted queue's work on dense zero-cost recursive joins, a useful event
budget, the conservative overflow refusal's accepted-source coverage, cold
support/closure checker cost, and WASM's eager workspace reservation. These
are named gates, not assumptions that Boolean or grounded results already
settle them.

* Mystery ledger and closeout

The extra-juice/terence-tao pass asked whether a proof witness must travel
with every result row. It need not: a checker can reconstruct a well-founded
support relation from the final values and then prove closure. This removes
the proposed trace's output and evaluator-state costs while retaining the
full semantic proof. The binding envelope alone is deliberately not called
a proof; independent checking is the acceptance gate.

| Question | Disposition and exact next gate |
|-
| Can detached checking alter the evaluator code through ThinLTO? | Open until C1194's opt-in/ordinary A/B compares the evaluator symbol, instructions and result bytes; isolate linkage if it does. |
| How expensive is support reconstruction for dense zero-cost joins? | Open until C1194 profiles checker work separately; optional rank sidecar is a measured successor only. |
| Does the conservative overflow rule reject useful bounded answers? | Known coverage cost; C1194 tests and reports a dominated-overflow case before any relaxation of the rule. |
| Does non-Unix eager =Pages= reservation fit the weighted workspace budget? | Open until C1194 native, WASM and host-memory sizing gates. |

No further architecture ambiguity remains for C1194. These are measured
implementation risks, not reasons to reopen the kernel/certificate choice.
