* Implemented rejection boundary

1. Validate shared readout and closure shape before any dictionary rebuild or
   unchecked indexing: parallel lengths, supported arities, tuple divisibility,
   bounded dense dictionary IDs, valid value kinds/payloads and closure IDs.
2. Validate each complement's source/relation/arity and each domain's position,
   provenance, historical dictionary range and bounded product before allocation.
3. Whitelist filter and aggregate operators; validate aggregate column/group
   shape, source closure and dictionary prefix before rebuilding.
4. Require canonical set closures where replay relies on set semantics; compare
   aggregate dictionary extensions as well as counts/digests.
5. Preserve successful producer outputs and existing explicit mismatch returns;
   replace panic characterizations with direct rejection assertions. Tests must
   cover adjacent partial-row, aggregate and forged-domain paths, not only the
   two originally observed index failures.

Astra red-teams the boundary and reviews the final patch; primary checks the
implementation and gates. Source metadata that cannot be authenticated from
this container alone is documented rather than advertised as verified.

* Cost and validation plan

The repair belongs at the cold replay boundary. The preflight adds
O(D log D + R log R + T) work for dictionary entries, relation names and closure
values, plus text comparison and per-record domain/provenance checks; allocation
and reconstruction already occur in this replay operation. No savings are
predicted. Evaluator loops and trusted producer construction should be unchanged.

Retain the existing Rel benchmark executable before source edits. Use matched
valid-input cohorts to check exact outputs and same-module ThinLTO movement;
measure replay overhead separately if the existing harness exposes that stage.
Source/compiler identities and any intentionally changed fingerprints must be
reported separately from result/work parity. No native portability claim follows
from a Linux measurement or wasm32 compilation.

Required gates: malformed-input regression matrix with valid controls, existing
Rel lowering/record tests, pinned formatting and relevant Clippy/build checks.
Broaden only where the dependency/feature surface changes. Final receipt records
actual commands, source snapshot, results and limitations.


* Review record

Sol implemented the repair; primary and the already-running Astra reviewer
independently checked the boundary. Primary owns final acceptance and subsequent
review, following the user's direction to use Sol subagents without additional
Astra subagents.

Review corrections before acceptance:

- Replace quadratic prefix scans for duplicate dictionary values/relation names
  with cold borrowed-key BTreeSets. At 65,536 dictionary entries the former
  approach could perform roughly 2.1 billion comparisons.
- Enforce the supported arity bound and test true partial binary rows; a unary
  row mutation only tested canonical ordering, not tuple divisibility.
- Reject unknown operators using controls matching the old fallback behavior,
  making the regression distinguish operator validation from digest mismatch.
- Check canonical integer spelling and unique typed values, not only successful
  parsing; validate even a result carrying no materialization records.
- Bind reconstructed aggregate extensions to the final typed dictionary prefix,
  and reconcile total facts/bytes with the supplied records using checked sums.
- Put the source/certificate authority limitation in the public replay rustdoc.

The focused Rel lowering suite passes 57 tests. It includes the existing
independent fixture oracle, valid complements/filters/all four aggregates,
empty dictionary/closures, and explicit malformed-input rejection. Logical
nullary programs are refused by lowering; there is no claimed producer-valid
nullary test. Replay retains its physical row-width convention =max(1, arity)=.
This bounded test set is not exhaustive over all hand-built public values.

* API mapping and unchanged obligations

| Surface | Before | This increment |
|---------+--------+----------------|
| =verify_records(&Stratified)= | Could panic or use unchecked defaults on malformed public shapes | Same signature; guarded replay returns explicit mismatch |
| =Error::ComplementMismatch(index)= | Primarily documented for complements | Same variant; documented across all three record families; index 0 also represents shared-shape/summary failure |
| =Stratified= / =Readout= | Public mutable records | Still public; validation occurs at replay entry |
| Core trusted admitted checker | Caller-owned admitted invariants | Unchanged |
| Source, certificate and layer authority | Supplied separately from this container | Still not authenticated by this replay operation |

Type-range metadata is checked for known kinds and range bounds; exact source
column typing and temporal provenance require source/layer evidence. Declared
relation IDs, literal IDs and use counts are not authenticated against missing
layer programs. The four overall materialized facts/bytes counters are reconciled;
other layer accounting remains descriptive. These limits belong to the broader
API/evidence work, not a claim of universal malformed-input authenticity.

* First measured variant — rejected for aggregate code generation cost

The [[file-rev:743e011:~/src/ergodis-private/analysis/rel-frontend/c1215-replay-variant1.json][committed first-variant receipt]]
retains all counter samples, A/A controls, parity, profiles and disassembly
hashes. All actual samples agree exactly; event enablement is 100%.
Nevertheless, the aggregation fixture consistently increased whole-stage
instructions by about 0.095% (284–311 instructions per iteration), while lower
stage differences were only 1–15 instructions. Other cohorts were near parity.
Cycle intervals included unity; that does not negate the instruction regression.

The unchanged =evaluate= symbol has the same 30,311-byte size and 5,716-mnemonic
sequence. =aggregate_over= shrank from 3,479 to 3,029 bytes, with a new ordinary
out-of-line =SpecToString::spec_to_string= call replacing previously inlined
integer formatting. The new canonical-integer validation's =to_string= call
is a specific plausible compiler-inlining cause. This is not an isolated replay
cost: the timed loop does not run record replay. The primary rejected the
performance disposition rather than silently accepting the small regression.

One narrow experiment replaces that cold formatting comparison with an
equivalent check: successful i64 decimal parsing, and either exactly =0= or an
optional minus followed by a first digit 1–9. Parsing checks all remaining
digits and range; the prefix rule excludes plus signs, leading zeros and =-0=.
New tests reject =+1=, =00=, =-0= and =-01= and accept negative values and both
i64 endpoints as well-shaped dictionary entries. Evaluator helpers are unchanged.

Prediction before measuring: if the new formatting call changed inlining,
removing that call should restore the old aggregate formatting path and recover
roughly the observed 300 extra instructions per aggregation iteration. This is
a bounded compiler hypothesis, not a claim of proven instruction attribution.
