## What was implemented

All in `notes/2026-07-06-grid-cap-solver.rs` (working tree, uncommitted):

- **New mode `esc <q> [--cap <slots>] [class-index...]`** (dispatch in `main`, after the
  `escape` branch; accepts `--cap N` or `--cap=N` anywhere after the mode word; remaining
  positional integers = q first, then optional class indices).
- **`solve_esc(q, filter, cap)`**: enumerates canonical size-3 classes with the existing
  `enumerate(&b, 3, ...)` machinery (identical to `escape` mode's phase 2 — same class set,
  same order, so class indices are stable across runs and match `escape`'s iteration order).
  For each selected class: a **PRIVATE `FnvMap<u128,bool>` memo** is created, the class's
  subtree is fully expanded with `esc_g`, escape = # P size-4 children is counted by canon
  lookup in that private memo, and the memo is **dropped** at the end of the iteration.
  No global arena, single-threaded, small constant RSS.
- **`esc_g(...) -> Option<bool>`**: the existing `Solver::g` full-expansion recursion
  (full=true semantics: no early break, so every size-4 child gets memoized), minus the
  defect diagnostics, over the private memo, keyed by the SAME global `Board::canon` —
  sound per spec (within one subtree the global canon merges more, never less; game value
  is a G-invariant). Returns `None` when `memo.len() >= cap` at a fresh node ⇒ the abort
  propagates up and the class is reported **ABORTED** with the size reached; the run
  continues to the next class.
- **Per-class output line**:
  `CLS q=.. cls=<i> S3=[(r,c)x3] escape=.. bad=.. total=.. peak-memo=.. status=OK`
  or `... status=ABORTED peak-memo=.. cap=..` (also `status=OUT-OF-RANGE` for a bad index).
- **Summary**: on a FULL unfiltered run with zero aborts, prints the `escape`-mode summary
  line and histogram line **byte-identically** (root derived via the frame reduction:
  root=N iff some class has escape 0), plus one extra line
  `peak-private-memo max over classes = ..`. Filtered or aborted runs print a
  clearly-labelled `PARTIAL` summary instead (no root claim).
- Header mode-doc block updated with the `esc` usage.
- **No existing mode touched** — `escape`/`outcome`/`defect`/`par`/`feat`/`resym`/
  `breaks`/`checkpos`/`boundary` code paths are unchanged (verified: `escape` output at
  q=11/13 in this session matches its historical format and values exactly).

## Notes / caveats for the reviewer

- `--cap` counts **memo entries** (distinct canonical classes in the private memo), not
  bytes; std HashMap overhead is ~30–50 B/slot at these sizes.
- On an ABORTED class the escape count is not computed (full expansion is required for
  correctness of the escape lookup) — the class must be re-run with a larger cap.
- The root printed by a full `esc` run comes from the frame reduction (root=N ⟺ some
  size-3 class has escape 0), NOT from solving the root directly — this matches the
  proven reduction (`2026-07-06-frame-reduction.md`) and reproduces `escape`'s root on
  every case tested (q=11,13 exact; q=17/19 pending the gate).
- The q=23 campaign itself is explicitly OUT OF SCOPE until the G(17) queens nimber run
  frees the box (day-plan constraint).
